# Локальный сервер 4tox

Без npm-зависимостей: статика + лобби 2–4 + релей сообщений.

```bash
node game/server/server.js            # 0.0.0.0:8787 + проверка сети
node game/server/server.js --tunnel   # плюс HTTPS-ссылка через pinggy
node game/server/server.js --local    # только 127.0.0.1, для одного
node game/server/server.js --open     # плюс открыть браузер
node game/server/server.js --port 9000
```

Двойной клик по `game/Мультиплеер.command` запускает `--tunnel --open`.

## Главное: почему «мой IP не отвечает»

У домашнего интернета бывает **CGNAT**: провайдер не даёт компьютеру
публичный адрес, а сажает его за общий NAT. Признак — роутер получает адрес
из `100.64.0.0/10` (или приватный), а сайты видят совсем другой IP. В этом
случае **входящие соединения до компьютера не доходят вообще**: ни ссылка по
IP, ни проброс порта в роутере не помогут — пакет умирает на стороне
провайдера.

Сервер проверяет это сам при запуске (через UPnP у роутера) и пишет в окно
прямо:

```
СЕТЬ: Archer C64, внешний адрес 100.118.36.208
ВНИМАНИЕ: провайдер держит вас за CGNAT (...)
Публичный IP 213.239.158.37 — общий; входящие до вас не доходят.
Проброс порта НЕ поможет: по внешнему IP друзья не зайдут.
```

Если CGNAT нет, сервер пробует **сам пробросить порт** через UPnP и пишет
ссылку по внешнему IP. Если UPnP выключен — порт надо пробросить вручную
(`TCP 8787` на IP этой машины); отключается флагом `--no-upnp`.

### Что работает при CGNAT

1. **Hamachi (это и есть «мой IP»).** В окне сервера и в лобби есть адрес
   вида `http://25.33.95.200:8787/game/`. Друг ставит LogMeIn Hamachi, входит
   в вашу сеть — и открывает этот адрес. Трафик идёт через Hamachi, CGNAT ему
   не мешает. В лобби это отдельная строка со своей кнопкой «копировать»;
   при запуске без `--tunnel` она главная, с `--tunnel` главная — HTTPS-ссылка.
2. **HTTPS-ссылка через туннель (`--tunnel`).** Другу ничего ставить не надо:
   он открывает `https://….pinggy.net/game/?lobby=XXXXX`, **один раз** жмёт
   «Enter site» на странице-предупреждении pinggy (это защита бесплатного
   туннеля) и играет. Первая загрузка идёт через релей: атласы игры весят
   ~9 МБ, поэтому это может занять до минуты. Дальше браузер их кэширует.
   Бесплатный туннель живёт час, потом адрес меняется — лобби покажет новый.
3. **Публичный IP.** Только если провайдер даёт входящие соединения (не
   CGNAT) и порт проброшен. Самый быстрый вариант, но зависит от провайдера;
   иногда достаточно позвонить и попросить «белый IP».

## Почему не cloudflared

Туннель cloudflared буферизует `text/event-stream`: события «кто вошёл», «кто
готов», «старт» и снапшоты не доезжают до браузеров. Именно из-за этого
раньше было «оба нажали Готов, а игра не началась». Pinggy — обычный
SSH-туннель, он стримит SSE как есть, поэтому годится.

Даже без туннеля SSE может порваться (ноутбук уснул, Wi-Fi моргнул). Поэтому
у лобби есть второй канал: пока экран лобби открыт, клиент опрашивает
`GET /api/status` раз в 1.5 с. Опрос возвращает то же состояние, что SSE, и
уже случившийся старт — старт не теряется. Сам старт начинает хост кнопкой
«Начать игру»: автостарт «как только все готовы» оставлял за бортом друга,
который ещё открывал ссылку.

## Как устроено

- `POST /api/lobby` — создать; `POST /api/join` — войти по коду;
  `POST /api/ready` — готовность; `POST /api/start` — старт (только хост);
  `GET /api/status` — состояние лобби и старт (опрос); `GET /api/events?code&token`
  — SSE вниз; `GET /api/server` — адреса сервера, CGNAT и туннель;
  `GET /api/ping` — круг для индикатора связи; `GET /api/resume` — вернуть
  сохранённую партию после F5 (тот же токен, последний снимок);
  `POST /api/command` — команда клиента хосту; `POST /api/snapshot` — снапшот
  хоста клиентам.
- Сервер не знает правил игры: он пересылает `command` хосту и `snapshot`
  клиентам. Мир считает только хост. Вкладку хоста можно сворачивать: время
  мира догоняется по стенным часам (`game/js/boot.js` → `advance`). Браузер в
  глубоком фоне всё равно может редить таймеры снапшотов, поэтому клиенты в
  такие минуты увидят редкие скачки, а не остановку мира.
- Лобби стартует по кнопке хоста, когда все нажали «Готов». Игроков 2–4;
  карта одна (192), старт одинаковый — ратуша, дом, лагерь лесоруба, три
  жителя.
- Игрок, у которого пропала связь, остаётся в лобби 45 секунд: `EventSource`
  переподключается сам, и после возвращения «готов» и место в лобби те же.
  Если не вернулся — убирается, а хост (если ушёл он) передаётся следующему.
- **Уход хоста в партии** замораживает мир у клиентов, но НЕ выкидывает их в
  меню: последний кадр остаётся на экране, бейдж говорит «нет связи», игрок
  ждёт. Мир живёт во вкладке хоста, передать его нечем. Если оборвался только
  SSE, а снапшоты или heartbeat `GET /api/ping?code&token` идут, сервер не
  объявляет хоста пропавшим: любой запрос от него — доказательство жизни.
  Запас — `HOST_GRACE = 60 с` (восьми не хватало: один долгий кадр или
  моргнувшая сеть выглядели как уход). Вернулся — приходит `host-back`,
  партия продолжается.
- **Снимки не топят канал.** Хост шлёт их из `Play.tick` через `netSend`:
  база 80 мс, а если круг POST длиннее 420 мс — интервал плавно растёт до
  200 мс. Так у друга не растёт пинг из-за очереди устаревших кадров.
- **F5 не выкидывает в меню.** Клиент хранит код и токен лобби в
  `localStorage` под ключом ЭТОЙ вкладки (`sessionStorage` помнит её id) и на
  старте зовёт `GET /api/resume`: тот же игрок, тот же город. Сервер держит
  последний снимок партии; клиент сразу рисует его, хост поднимает по нему
  мир и продолжает считать. Нового игрока через `/api/join` после старта
  по-прежнему взять нельзя — это именно возврат, а не вход. 
- Наружу отдаются только `game/` и `mapgen2/`: корень репозитория (`.git`,
  документы, инструменты) по сети не ходит.

## VPS за reverse proxy (Caddy)

Сервер можно держать не на домашней машине, а на VPS. Node слушает только
loopback, наружу его отдаёт Caddy:

```bash
node game/server/server.js --host 127.0.0.1 --port 8787 --no-upnp \
  --public-url https://game.example.com/game/
```

- `--host` — не открывать порт Node в интернет. Раньше это умел только
  `--local`, но он ещё и отключал проверку сети, и лобби показывало ложное
  «порт наружу не проброшен».
- `--public-url` — единственная ссылка, которую лобби показывает друзьям.
  Без него `serverView` считает, что порт наружу не проброшен, и рисует
  предупреждение, хотя HTTPS уже работает.
- Caddy: `handle /game/*`, `/mapgen2/*`, `/api/*` → `reverse_proxy
  127.0.0.1:8787 { flush_interval -1 }`. `flush_interval -1` обязателен для
  SSE: иначе события лобби и снапшоты копятся в буфере.
- Статика отдаётся с `ETag`: повторный вход не скачивает 10 МБ атласов
  заново, браузер получает 304.
- Служба systemd: `WorkingDirectory=/opt/4tox`, `User=4tox`,
  `ExecStart=/opt/node/bin/node game/server/server.js ...`,
  `Restart=on-failure`.

Проверено на VPS 2 vCPU / 4 ГБ: Node ~60 МБ RSS, Caddy ~110 МБ, четверо
играют без упора в CPU. Узкое место — не железо, а канал хоста: 12.5
снимков/с по 8–30 КБ.

## Производительность сети (правила, которые нельзя откатывать)

Раньше каждый снимок (10 раз в секунду) тащил **весь** массив срубленного,
клиент заново создавал все постройки и жителей и пересобирал обзор на новый
холст. К середине партии это давало лаги, а браузер мог выбросить кэш
местности — оставалась одна вода. Сейчас:

- **Снимок нумерован** (`seq`). Клиент применяет только более новый: ответ,
  приехавший не в том порядке, не откатывает мир.
- **Убранное — битовая карта** hex-строкой (`objectTotal` бит), а не массив
  номеров. Размер не растёт с числом срубленного. Старый формат-массив
  `Serialize.apply` ещё понимает.
- **Один снимок в пути.** Хост шлёт из игрового цикла (`Play.tick`), а
  следующий — только после ответа на предыдущий. При медленной сети кадры
  редеют, а не копятся в очереди. 80 мс (12.5 Гц) — база; если круг POST
  дольше 420 мс, интервал сам поднимается до 200 мс, чтобы хост не забивал
  свой канал. Движение между снимками сглаживает клиент
  (`netSmoothVillagers`).
- **Сверка по id, а не пересоздание.** `Serialize.apply` переиспользует
  объекты построек и жителей. Выбранный житель, открытая постройка, отряд и
  таблички не сбрасываются на каждом снимке.
- **Обзор пересобирается только при изменении состава/места построек или
  рубки**, а не на каждый снимок. Холст обзора переиспользуется.
- **Сервер не копит SSE.** Если поток клиента отстал (`writableLength`), снимок
  для него пропускается: следующий всё равно абсолютный. `setNoDelay` убирает
  40-мс задержку Nagle на командах и «готов».
- **Команда едет не только SSE.** `POST /api/command` кладёт её в очередь
  лобби, а хост забирает очередь в ОТВЕТЕ на свой `POST /api/snapshot` (поле
  `commands`) и подтверждает номером `cmdAck` в следующем снимке. Раньше
  команда шла только событием SSE: обрыв потока у хоста терял клик молча —
  снимки продолжали идти, а постройка не появлялась («здание встало через
  полминуты»). Очередь чистится по ack, повтор с тем же `n` не задваивается,
  через `CMD_TTL = 15 с` команды пропавшего хоста выбрасываются. Событие
  `command` сервер всё ещё шлёт — для старого хоста, который не умеет
  забирать ответ снимка; новый хост его не слушает, чтобы не было двух путей
  с разным порядком.
- **Команды идут по одной**, с повтором и номером `n`; хост отбрасывает
  повторный номер. Хост проверяет цену постройки и списывает брёвна у деревни
  автора команды, а не у хоста.

## Проверка

```bash
node game/tools/mp.js       # без интернета; сервер, лобби, старт, снапшоты
node game/tools/menu.js     # игра в браузере
```

`mp.js` поднимает сервер и Chrome, создаёт лобби, входит вторым игроком,
нажимает «Готов» **кнопками** у обоих, проверяет, что сам старт не случился,
и жмёт «Начать игру» у хоста. Дальше — движение жителя, урон, снапшоты,
команда гостя и списание брёвен. Отдельно проверяются ссылка-приглашение (не
`127.0.0.1`), старт без SSE (только опросом), возврат с тем же токеном,
передача хоста, «дыра» в id игроков, третий игрок не остаётся за бортом,
компактность снимка после сотен срубленных, сохранение объектов/выбора между
снимками, остров на клиенте (не только вода) и экран потери хоста.

Туннель проверяется вручную: `--tunnel`, открыть ссылку, один раз нажать
«Enter site», создать лобби и войти вторым браузером. Он зависит от внешней
сети, поэтому в `mp.js` не входит.
