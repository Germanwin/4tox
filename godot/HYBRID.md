# Гибридный клиент: как это устроено

Короткая память для следующих сессий. Порт перестал быть «второй игрой»:
правила и мир остаются на сервере, Godot — только глаза и руки.

## Роли

| Кто | Что делает |
|---|---|
| Node-сервер (`game/server/*`, комнаты в worker) | единственный источник правил и состояния |
| Godot | лобби по REST, кадры по WebSocket (`4TX1` v2), команды `POST /api/command`, отрисовка |

В GDScript **нет симуляции**. `ToxSim`, `worldgen.gd`, `pathfinder.gd`,
`villager.gd` (правила), `combat.gd` из прототипа не используются гибридом.

## Что доказано (числа — из `test_render.gd`, порог 0.5 %)

### Земля, природа, постройки, жители

Гейт: `./tests/visual.sh` — 3 карты × 18 кадров (54) (`tests/fixtures`,
`tests/fixtures/m192`, `tests/fixtures/m96`). Эталоны снимает
`node tests/capture_reference.js` из настоящего `game/index.html` на тех же
сидах, что у сервера.

| кадр | 192 каменная | 192 тихая | 96 тихая |
|---|---|---|---|
| земля z24/40/64 | 0.004 / 0 / 0 | 0.001 / 0 / 0 | 0.251 / 0.091 / 0.000 |
| природа z24/40/64 | 0.004 / 0.000 / 0 | 0.003 / 0 / 0 | 0.208 / 0.070 / 0.000 |
| постройки z24/40/64 | 0.038 / 0.017 / 0.057 | 0.034 / 0.016 / 0.060 | 0.284 / 0.108 / 0.059 |
| газон z24/40/64 | 0.038 / 0.017 / 0.057 | 0.034 / 0.016 / 0.060 | 0.284 / 0.108 / 0.059 |
| жители z24/40/64 | 0.006 / 0.004 / 0.007 | 0.003 / 0.003 / 0.007 | 0.251 / 0.094 / 0.007 |
| общий кадр z24/40/64 | 0.044 / 0.028 / 0.081 | 0.044 / 0.030 / 0.092 | 0.247 / 0.094 / 0.077 |

Формат ячейки: проценты пикселей с расхождением >12/255. Все 54 кадра
(3 карты × 18) проходят порог; `visual.sh` зелёный, `FAIL` нет. Кадры
`build_*` и `plot_*` совпадают по числам, потому что эталон у них один и тот
же (ref_build снят уже с газоном, ref_plot — тот же кадр под своим именем).

Правило фильтра: если спрайт уменьшается сильнее чем вдвое, трилинейные
мипмапы Godot размывают кромку сильнее Chrome; Chrome ведёт себя как ОДИН
уровень мипмапа. Поэтому при z < 32 — `textureLod(1.0)` и
`LINEAR_WITH_MIPMAPS`, иначе обычный `LINEAR`.

## Ключевое решение: клиент не генерирует остров

Сервер один раз отдаёт статический мир (`GET /api/world`, формат `WLD1`,
`game/shared/world-wire.js`, декодер `scripts/world_wire.gd`): тайлы,
`isLand`, `distLand`/`distWater`, объекты природы. Клиент ничего не
генерирует; «можно ли ставить дом» по-прежнему решает сервер.

## Газон участка (сделано, в гейте)

`scripts/plots.gd` — порт `Renderer.bakeTurfTexture`:

* **кромка**: точки через 0.085 клетки, дрожание ±0.10, тот же LCG и тот же
  порядок вызовов, что в браузере (полигон и список кромок для бахромы);
* **маска**: браузер заливает путь в холст с `filter: blur(22px)` и режет по
  clip пути. Замер длинной прямой кромки в Chrome: сигма 23 px, модель
  `Phi(d/σ)` даёт RMS 2.4/255. Поэтому маска — `Phi(d·BAKE/√5 / 23)`,
  обрезанная по полигону: край ЖЁСТКИЙ, размытие идёт ВНУТРЬ. Это и был
  главный секрет: первый проход размывал наружу и не сходился (0.578 %);
* **плитка**: 2×2 клетки, 4 поворота, фаза `(X − phx) mod tile` — знак
  измерен пробой canvas-паттерна (не «на глаз»);
* **бахрома**: 4 тона, 4 лезвия на угол, квадратичные кривые, растеризация
  2×2 суперсэмплингом.

Газон теперь включён и в `ref_build`, и в `ref_full`; `capture_reference.js`
больше не глушит `drawPlots` для этих кадров, `render_build.gd` рисует через
`WorldLayer` (тот же путь, что игра), `render_world.gd` — с газоном.

## Вода, пляж и море (сделано, в гейте)

`scripts/ground_cache.gd` — порт `Renderer.paintCache`, теперь БЕЗ
SubViewport и БЕЗ рендера: все проходы считаются в GDScript по пикселям
кэша, поэтому одинаковы в headless и в игре.

* **море за краем сетки**: кэш заливается «глубиной с бликами» (цвет DEEP,
  умноженный на ripple, `0.15 + 0.85·r` — как `drawSeaTexture`, multiply
  0.85). Это и был обрыв моря: раньше за картой лежал газон;
* **глубина**: картинка W×H (клетка = пиксель), растянутая билинейно
  (центры пикселей — в целых координатах клеток). Глубина за полосой 6.4
  клетки — ровно DEEP, поэтому per-pixel работа идёт только по прибрежной
  полосе;
* **кромка суши**: объединение ромбов клеток с покрытием 1 px
  (`_cell_cov`), наклон кромки — `1/√5` cache px на клетку. Рост пути
  (canvas `OVERLAP`) подобран замером: 0.4 у суши, 0.45 у песка
  (при 0 — 0.83 %, при 1.0 — 0.85 %);
* **песок**: сплошная полоса `distWater ≤ 1.2` + дизеринг на 2–3 ряда
  (тот же `hash2`, те же зерна-ромбы); иначе внутренняя кромка полосы не
  сходилась — это и дало 0.83 % → 0.25 %;
* **мокрый песок**: альфа-картинка на клетку, билинейно, с обрезкой по
  суше;
* **что НЕ рисуется**: гребни волн (`drawWaterShimmer`). В браузере они
  отсекаются по `WAVE_MIN_PX = 9`: при разрешённых зумах (≤120)
  `sc.x·12 < 9`, то есть волн нет ни на одном кадре игры. Если зум поднять
  выше ~127, их придётся добавить.

Цена: сборка кэша m96 — ~1.5 с (профиль: вода 0.56, суша 0.11, песок 0.67,
мокрый 0.28 мс-секунд), кэш 3026×1514. Это разовая работа на матч.

## HUD гибрида (сделано, допуск согласован)

`scripts/hybrid_hud.gd` — Control-ноды в теме `ToxUI`:
верхняя строка (брёвна/жители/воины/учатся/срублено/доставлено из
`towns[owner]`), строка событий/ответа сервера, кнопки «Стройка», «Правка»,
«Войска», «Меню».

* **Стройка** — карточки `BUILD_MENU` (те же цены, что в игре: 12/20/28/24),
  клик по карте отправляет `build` с `buildingType/variant/rot/x/y`;
  призрак пятна рисует `hybrid_ghost.gd`; место проверяет сервер.
* **Правка** — выбор постройки кликом, «Повернуть»/«Переместить»/«Снести»/
  «Отменить» → команды `edit` (`rotate`/`move`/`delete`).
* **Войска** — группы по лагерям, «Всех»/«Половина»/«Сброс», «Приказ»
  (клик по карте → `order`), «Стоп» → `stop`.
* **Меню** — «Продолжить», «Новый остров» (переподключение комнаты),
  «В главное меню»; игра не останавливается.

Команды идут ТОЛЬКО через `POST /api/command` + опрос `/api/command-state`
(`live_room.gd: send_command`), с `commandId = instance:seq`, которые выдал
сервер в стартовом пакете.

Приёмка: `tests/test_hud.gd` — 37 проверок структуры и ТОЧНЫХ payload-ов
команд (без сети: подставная комната); `tests/render_hud.gd` — живые кадры
`shots/hud.png`, `hud_build`, `hud_edit`, `hud_edit_after`, `hud_army`,
`hud_menu`. Пиксельного эталона к DOM у HUD нет — согласован перцептивный и
структурный допуск.

Чего в HUD нет: найма/тренировки воинов (в браузере это отдельные кнопки),
групповых колец выбора на карте, подсказок места до клика. Это следующий
слой, а не забытая галочка.

## Одиночная партия и кроссплей (сделано)

* `POST /api/start {solo:true}` снимает требование второго игрока
  (`server.js: startBlock`), а комната поднимает одиночный мир:
  `mode:'solo'` → `Session.startSoloCore` (одна деревня, три жителя),
  `Session.standing` для одной деревни не объявляет победу сразу.
  Это аддитивно: без `solo:true` всё как было (нужно двое).
* `tests/test_live.gd` — сам поднимает сервер, входит в одиночную комнату,
  получает `WLD1`, снимок `4TX1` (1 деревня, 3 постройки, 3 жителя) и
  ПОВОРАЧИВАЕТ ратушу командой; снимок показывает новый поворот.
* `tests/test_crossplay.gd` — Godot создаёт лобби и ждёт, настоящий Chrome
  (`tests/browser_guest.js`) входит по коду и жмёт «Готов», хост стартует.
  Проверено: у обоих 2 деревни, 6 построек, 6 жителей, одинаковый сид,
  браузер видит 3 дома Godot и свой город, транспорт `ws`, команда хоста
  `edit/rotate` применена. 16/16.

## Живая комната

`scripts/live_room.gd`: лобби по HTTP, `solo` или хост-режим с ожиданием
второго игрока, `WLD1`, `/api/ws`, кадры `4TX1`, команды. Меню «Живая
комната» подключается к `http://127.0.0.1:8787` (сервер запускается вручную:
`node game/server/server.js`). Скриншот: `Godot --path . -- --shot=live`,
демо-фикстура — `--shot=hybrid`, HUD-кадры — `tests/render_hud.gd`.

## Что осталось / известно

* HUD: найм и тренировка воинов, кольца выбора отряда, подсветка места до
  клика. Пиксельного паритета с DOM нет по согласованию.
* Кайма в батче рисуется перед спрайтами куска: в плотной толпе возможен
  1 px перекрытия (см. BATCHING.md).
* Сборка кэша земли ~1.5 с блокирует старт матча (m96); можно увести в
  поток, если станет мешать.
* Замер на целевом железе — за заказчиком.
