# 4tox — клиент на Godot 4 (гибрид)

Изометрическая деревня 4tox. **Мир и правила считает Node-сервер**
(`game/server/*`, комнаты в worker), Godot — глаза и руки: лобби по HTTP,
статический остров `WLD1`, кадры `4TX1` v2 по WebSocket, команды
`POST /api/command`, отрисовка и HUD. В GDScript нет симуляции — одна копия
правил, та же, что в браузере.

Атласы, текстуры и модели взяты из `mapgen2/assets` и `art/**/out`;
`tools/sync-assets.sh` обновляет копии.

## Запуск

Двойной клик по `run.command` (или из терминала):

```bash
cd godot
./run.command
# то же вручную:
/Applications/Godot.app/Contents/MacOS/Godot --path .
```

Терминал и ручной `node` не нужны: `scripts/server_supervisor.gd` находит
Node (рядом с приложением или в PATH), выбирает свободный порт, поднимает
`game/server/server.js --local --no-upnp`, ждёт `/api/health` и гасит процесс
при выходе. Лог — `user://logs/server.log`.

«Играть» — это **гибридная партия**. «Против деревни» — та же партия с
деревней бота (`bot:true`). Старый прототип `ToxSim` остался только
заставкой меню и отладочными кнопками «Новый рендер» / «Живая комната».

## Несколько окон (клиентов)

Каждый клик по `build/macos/4tox.app` открывает **новое** окно, а не
активирует старое. macOS по умолчанию считает запущенным приложение, которое
живёт окном, поэтому `4tox.app` — тонкий лаунчер: он вызывает
`open -n` для вложенного `Contents/Resources/4tox-client.app` и сразу
выходит. Клик по нему снова застаёт лаунчер «незапущенным», и окон можно
открыть сколько угодно. Настоящий клиент лежит отдельным `.app` со своим
bundle id (`tools/wrap_macos.sh`, встроено в `tools/package.sh`).

Кликать нужно по **файлу** `4tox.app` (его же можно закрепить в Dock): клик по
иконке уже запущенного клиента macOS по-прежнему активирует его окно. Если
после обновления остался старый запущенный клиент, закрой его один раз.

Окна независимы, и это важно для теста VPS/EOS:

- в заголовке — `4tox — клиент N`;
- у каждого своя сессия последней партии: `user://net-session.cfg` у клиента 1
  (старое имя, чтобы не ломать возврат в партию) и
  `user://net-session-N.cfg` у остальных;
- локальный Node-сервер каждого окна пишет в свой `user://state/client-N` и
  свой `user://logs/server-N.log`; два сервера на одном `state/rooms` читали
  бы и закрывали комнаты друг друга.

В разработке то же самое: `./run.command` дважды. Номер можно задать явно —
`./run.command -- --client=2` или `TOX_CLIENT=2 ./run.command`; без флага
выдаётся первый свободный. Занятость — каталог-замок
`user://instances/client-N` с ударом сердца внутри: живое окно обновляет его
дважды в секунду, брошенный замок забирает следующее окно.

EOS: первый запуск после обновления один раз спросит доступ к связке ключей
(`com.epicgames.sdk.connect.access_token`) — нажми «Разрешать всегда». Клиент
подписан стабильным requirement (`tools/sign_macos.sh`), поэтому после этого
пересборки больше не спрашивают. Пароль связки приложению не нужен.

EOS: анонимный device id один на машину. Окна входят под общей очередью
`user://eos-login.lock` и получают **свои** Product User ID, поэтому хозяин и
гость — разные игроки; `DuplicateNotAllowed` больше не тупик (при занятом
device id клиент входит существующим, а не падает). Пустое EOS-лобби, куда
никто не зашёл, само закрывается через 30 секунд. Проверка —
`tests/eos_pair.sh` (две настоящие копии, пакет туда-обратно).

Приёмки: `tests/test_client_profile.gd`, `tests/test_multi_windows.gd` и
`tests/multi_app.sh` (три клика по собранному `.app` → три живых клиента).

## Сеть

«Сеть» в главном меню — это HTTP/WS того же сервера, что у браузера, без
ENet. Хост нажимает «Создать игру» и получает код, друг вводит код и имя,
оба жмут «Готов», хост — «Начать игру». У каждого своя деревня и цвет,
остров и правила считает сервер, команды применяются им же; играть можно
Godot↔Godot и Godot↔Chrome. Адрес сервера — origin без `/game/`
(`https://374412.fornex.cloud:8443` для VPS; локальный поднимается сам).
Прод обновлён 2026-11-03 (build `21592ed64770`), 443 и 8443 проверены.

**Два входа и честная причина отказа (2026-11-04).** 443 на VPS делит
листенер с naive-прокси: при включённом VPN первый заход иногда получает
`407 Proxy Authentication Required` или теряет соединение вовсе, хотя адрес
верный. Поэтому клиент:

- повторяет сетевой сбой ДО отправки (до трёх раз, пауза 0,35 с): на 443
  второе соединение обычно проходит, а повтор ничего не создаёт дважды;
- если основной вход не ответил по сети **или ответил `407` от прокси/VPN**,
  идёт **запасным** — тем же origin на `8443` (отдельный сайт Caddy без
  `forward_proxy`) — и показывает в поле адреса и в статусе, каким входом
  играет: «… · вход https://374412.fornex.cloud:8443»;
- отказ называет **словами**: «нет связи: не удалось соединиться», «HTTP 407
  — это прокси или VPN, а не игровой сервер», «HTTP 404 — на этом адресе нет
  игры (нужен origin без /game/)», причину сервера («на сервере слишком много
  лобби…»). Старое «локальный сервер не ответил: проверьте адрес» на 407 от
  прокси уводило чинить верный адрес;
- адрес без схемы дополняется (`374412.fornex.cloud` → `https://…`,
  `127.0.0.1:8787` → `http://…`), хвостовой `/` и `/game/` срезаются.

Проверка — `tests/test_net_entry.gd` (30 проверок) на заглушках
`tests/fake_entry.js`; прод не трогается.

Сессия последней партии хранится в `user://net-session.cfg`; после падения
клиента (и при игре через VPS) приложение само возвращается в ту же комнату
через `GET /api/resume`. Кнопка «Продолжить» на экране сети делает это вручную.
Штатный выход в меню сессию стирает.

## Прототип (не игра)

`scripts/sim.gd`, `worldgen.gd`, `pathfinder.gd`, `villager.gd` — старый
полный порт со своей симуляцией. Он **не** используется в главном пути:
другая копия правил — ровно то, из-за чего прошлый порт разъехался. Код
оставлен для заставки меню и сравнения; правила берутся только с сервера.

## Сборка

`./tools/package.sh` собирает `build/macos/4tox.app` (лаунчер + вложенный
`4tox-client.app`) и `build/windows/4tox.exe`, кладёт рядом бандл сервера (game/, mapgen2/, node для
macOS и **node.exe** для Windows), делает `build/4tox-macos.dmg` и
`build/4tox-windows.zip` и проверяет собранное приложение флагом `--smoke`:
оно само поднимает сервер, входит в партию и выходит 0. Нужны шаблоны экспорта
Godot той же версии (Editor → Manage Export Templates).

Для Windows есть отдельная сборка установщика:

```bash
./tools/package_windows.sh          # 4tox-0.2.0-windows-setup.exe + portable zip
./tests/test_windows_installer.sh   # приёмка: PE, PCK, node.exe, состав, /api/health
```

`package_windows.sh` экспортирует `.exe`, скачивает официальный Windows
`node.exe` (сумма сверяется по SHASUMS256), собирает NSIS-установщик с
установкой в `%LOCALAPPDATA%\Programs\4tox` (без UAC), ярлыками и
деинсталлятором. Сборка NSIS на macOS требует UTF-8-локали — скрипт ставит
`LC_ALL=en_GB.UTF-8` сам (баг NSIS #1165). На живой Windows установщик и игра
**не запускались** (машины нет). Проверено под Wine 11.21 на macOS: тихая
установка, ярлыки, запись в реестре, `Uninstall.exe /S`, а `4tox.exe
--headless -- --smoke` сам поднял `server\node.exe`, вошёл в партию
(3 постройки, 3 жителя) и вышел 0. Рядом с exe лежат `msvcp140.dll`,
`vcruntime140.dll` и `vcruntime140_1.dll` (VC++ 2015–2022, app-local), поэтому
EOS-расширение грузится и без установленного VC++ Redistributable. SmartScreen
и мышь на Windows не проверены.
