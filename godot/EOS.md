# EOS-режим в Godot-порте

Дата: 2026-11-04. **Отдельный режим, а не замена сети.** Меню → «EOS».
Основной путь «Сеть» (`net_lobby.gd`, `live_room.gd`, `net.gd`) не изменён:
у EOS-режима свой экран (`scripts/eos/lobby.gd`) и свой `LiveRoom`.

## 1. Как это устроено

```
хозяин:  Godot ── LiveRoom ──▶ 127.0.0.1:8787  Node-комната (мир, правила)
            │                        ▲
            │ Tunnel (host)          │ тот же порт
            ▼                        │
         EOS P2P ─────────────▶ Tunnel (host) ──TCP──┘

гость:   Godot ── LiveRoom ──▶ 127.0.0.1:<эфемерный>  Tunnel (guest)
                                                    │
                                                    ▼
                                              EOS P2P
```

* Мир считает Node-сервер. EOS заменяет **провод**, не авторитет.
* `tunnel.gd` — TCP поверх дейтаграмм: пакет `[тип][поток:2][данные]`, куски
  ≤900 Б, один поток = одно TCP-соединение (HTTP-запрос, WebSocket, SSE).
* Код комнаты — `<Product User ID хозяина>.<имя сокета>`, например
  `0002e50b…7614.t4x3195545`. Лобби EOS не используется: у нашего клиента
  `CreateLobby` отвечает `AccessDenied`, а для игры оно не нужно — код
  заменяет обмен идентификаторами.
* Код длинный (47–56 символов), поэтому на экране он лежит не надписью, а в
  поле «код для друга»: его можно выделить мышью и скопировать, а кнопка
  «Копировать» кладёт в буфер обмена всю строку целиком (`lobby.gd` →
  `copy_invite`). `p2p_link.split_code` выбрасывает пробелы и переводы строк,
  так что код, приехавший из мессенджера с переносом, всё равно принимается.
* Транспорт — `EOSGMultiplayerPeer` (RELIABLE, ordered) из аддона 2.3.1.

### Несколько окон и один device id (обновлено 2026-11-07)

Анонимный вход EOS заводит **device id на машину**, а не на окно. Если две
копии одновременно делают `delete_device_id` → `create_device_id`, вторая
получает `DuplicateNotAllowed`, и это ровно та ошибка, которую видел заказчик.

Сделано (`scripts/eos/p2p_link.gd`):

* кэш SDK у каждого окна свой (`user://eosg-cache/client-N`), но device id
  EOS — **один на машину**;
* создание/вход идут под общей очередью
  `user://eos-login.lock` (атомарный каталог, брошенный забирается через
  30 с): второе окно ждёт, а не лезет в device id первого;
* обычный вход не удаляет Device ID; при `DuplicateNotAllowed` он использует
  существующий. Несколько окон могут получить одну идентичность — независимые
  EOS-участники на одной машине пока не гарантированы.

Старый прогон `tests/eos_pair.sh` использовал удаление Device ID и не
подтверждает работу пары после изменения. Для проверки EOS теперь нужны
отдельные устройства; localhost-транспорт проверяет только игровой протокол.

### Keychain: требуется проверка подписанной сборки

В прежнем исследовании наблюдалась запись с именем
`com.epicgames.sdk.connect.access_token`. Её содержимое, вызывающая операция
и возможность работы без неё не подтверждены. macOS привязывает «Разрешать
всегда» к **подписи** приложения; у неподписанного клиента (и у старого
плоского `.app`, и у нового вложенного) она менялась, поэтому запрос
возвращался после каждой пересборки.

`tools/sign_macos.sh` подписывает вложенный клиент ad-hoc с явным
designated requirement, который зависит только от identifier:

```
designated => identifier "cloud.fornex.tox4"
```

`tools/wrap_macos.sh` (а значит, и `tools/package.sh`) подписывает так каждую
сборку; `tests/multi_app.sh` проверяет, что подпись валидна и в requirement
нет `cdhash`, но не доказывает отсутствие запросов. Для раздачи в интернете нужен Developer ID — тогда
requirement будет с сертификатом, а не только с identifier.

Запускать лучше из постоянного места (`build/macos/4tox.app` или
`/Applications/4tox.app`), а не каждый раз с нового тома dmg: путь тоже
участвует в доступе к связке.

### Пустое лобби закрывается через 30 секунд

Хозяин, к которому никто не зашёл, держит Node-комнату, сервер и EOS-сокет
не дольше `UNUSED_TTL = 30` (`scripts/eos/lobby.gd`). Таймер стартует при
создании комнаты, снимается при входе гостя и при старте партии; если гость
ушёл — взводится снова. По истечении: комната закрывается, сервер и сокет
гасятся, на экране «лобби … закрыто: за 30 секунд никто не зашёл», можно
создать заново. Сервер независимо закрывает партию без подключённых игроков
через `INACTIVE_TTL = 30000` (`game/server/server.js`, приёмка
`node game/tools/tests/mp-inactive.js`).

## 3. Как играть

### Петля (без Epic, две копии на одной машине)

1. Два окна `./run.command`, в обоих меню → **EOS**.
2. Окно 1: «Создать комнату» → код `7791`.
3. Окно 2: этот код → «Войти по коду»; оба «Готов», хозяин «Начать игру».

### EOS (нужны ключи, см. §4)

1. Оба кладут одинаковый `eos.cfg` и запускают одну и ту же сборку.
2. Меню → **EOS** → транспорт «EOS (Epic)».
3. Хозяин: «Создать комнату» → под строкой «код для друга» появляется
   **длинный код** вида `0002e50b…7614.t4x3195545`. «Копировать» кладёт его в
   буфер обмена — отправьте другу; можно и выделить код в поле и нажать
   ⌘C/Ctrl+C.
4. Друг: вставляет код в поле «код комнаты» (⌘V/Ctrl+V) → «Войти по коду».
   Код лобби Node приедет сам.
5. «Готов» у обоих → хозяин «Начать игру».

Код меняется при каждом запуске хозяина (анонимный вход даёт новый Product
User ID) — это нормально, передавать его надо на каждую партию.

## 4. Ключи Epic

1. [Developer Portal](https://dev.epicgames.com/portal) → продукт → **Product
   Settings** (`product_id`), **Sandbox/Deployment** (`sandbox_id`,
   `deployment_id`).
2. **Clients & Client Policies** → клиент: `client_id` и `client_secret`.
   Нужны включённые **Connect** и **Peer2Peer**; **Lobbies не нужны**.
3. Файл `~/Library/Application Support/Godot/app_userdata/4tox/eos.cfg`
   (одна и та же на обеих машинах, права `600`). **Значения в кавычках** —
   иначе `ConfigFile` не разберёт hex-строку:

```ini
[eos]
product_name="4tox"
product_version="0.1"
product_id="…"
sandbox_id="…"
deployment_id="…"
client_id="…"
client_secret="…"
```

Проверить пару без игры:

```bash
curl -u "CLIENT_ID:CLIENT_SECRET" -d grant_type=client_credentials \
  https://api.epicgames.dev/auth/v1/oauth/token
```

`200` — ключи живые; `401 invalid_client` — пара не та.

## 5. Что проверено

| Проверено | Чем |
|---|---|
| Туннель возит HTTP, `WLD1`, WebSocket и `4TX1` | `test_eos_tunnel.gd`, 20/20 |
| Команда гостя применяется | там же, `edit/rotate` → `applied` |
| Экран, отказ без ключей, возврат, гашение сервера | `test_eos_mode.gd` |
| **EOS: вход, сокет, пакеты между двумя процессами** | `eos_pair.gd` |
| **EOS: мир, кадры и команда через туннель** | `eos_pair_tunnel.gd` |
| Выход без segfault (release/shutdown SDK) | там же, exit 0 |
| Вход в **release-сборке** (свой login без гонки сигналов) | `4tox --headless -- --eos-probe` |

`eos_pair_tunnel` (2026-11-04, две копии на одной машине): хозяин поднял Node,
гость пришёл по EOS-коду, получил `WLD1` и кадры, повернул ратушу — хозяин
увидел поворот, оба процесса вышли с кодом 0.

| **Не проверено** | Почему |
|---|---|
| Две **разные** машины и разные NAT | нужен второй компьютер/сеть |
| Релейный путь (строгий NAT) | там же |
| Друг на Windows | в аддоне только macOS-библиотеки |

Вход сделан своим кодом, а не `HAuth.login_anonymous_async`: тот сначала
вызывает `delete_device_id`, а потом ждёт сигнал. В release-сборке сигнал
приходил раньше, чем выставлялся `await`, и вход падал
(`UnexpectedError` на удалении → `DuplicateNotAllowed` на создании). Теперь
обработчик подписывается **до** вызова, и release-сборка входит так же, как
отладочная.

Проверка собранного приложения без экрана:

```bash
build/macos/4tox.app/Contents/MacOS/4tox --headless -- --eos-probe
# EOSPROBE: start=true room=<код> err=
```

## 6. Ограничения прототипа

* **Нет подтверждений и повторов** в туннеле: полагается на RELIABLE-режим
  `EOSGMultiplayerPeer`; честного TCP-стека (окно, ретрансмиты, half-close)
  здесь нет.
* **2 игрока**, без F5-возврата и наблюдателя.
* `persist_session` выключен, чтобы режим не трогал `user://net-session.cfg`
  основного режима.
* EOS: только UDP; системные часы должны быть верны по UTC; релей добавляет
  задержку; квот и SLA на релеи в документации нет.
* `client_secret` в настольной игре извлекаем — для друзей терпимо, для
  публикации нет.
* Аддон падает на выходе, если не вызвать release/shutdown, — `p2p_link`
  делает это сам (`shutdown_eos`), экран зовёт его в `_exit_tree`.

## 7. Приёмка и откат

```bash
cd godot
./tests/eos.sh                                    # петля + экран
godot --headless --path . -s res://tests/eos_probe.gd        # EOS: вход + сокет
godot --headless --path . -s res://tests/eos_pair_tunnel.gd -- --host
godot --headless --path . -s res://tests/eos_pair_tunnel.gd -- --guest=<код>
```

Откат: убрать пункт `"eos"` из `scripts/menu.gd` (ветка в `main.gd` останется
мёртвой) или удалить `scripts/eos/`, `tests/*eos*` и автозагрузки
`EOSGRuntime/HPlatform/HAuth/HLobbies` из `project.godot`. Основной режим не
импортирует ни одного файла из `scripts/eos/`.
