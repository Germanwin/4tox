# art — производство моделей

Здесь делаются все модели, которые поездут в игру спрайтами. Каждая модель —
отдельный проект: своя геометрия, свой рендер, свой упаковщик в атлас.

```
art/
├── tools/          общие инструменты над всеми моделями (не проект)
│   └── model-stand/    стенд: смотреть все модели и кадры их атласов
├── buildings/      постройки — ставятся в пятно застройки
│   ├── townhall/       ратуша 4 x 3 и хижина 3 x 2 (общий пайплайн)
│   ├── villager_house/ прежний дом жителя 3 x 2 (игрой не грузится)
│   ├── starter_house/  дом жителя в игре: стартовый дом 2 x 3
│   ├── lumbercamp/     лагерь лесоруба 3 x 3
│   ├── barracks/       казарма 4 x 3 (тип barracks)
│   └── warcamp/        военный лагерь: площадка 5 x 5, модель 2 x 2 (в игру не подключён)
├── characters/     люди — ходят, имеют клетку и анимации
│   ├── villager/       житель: idle / walk / work × 8 поворотов
│   └── armored_villager/ рыцарь в броне и с мечом: idle / walk / work × 8 поворотов
├── props/          предметы — носятся в руке
│   ├── axe/            топор
│   └── shovel/         лопата
├── fx/             эффекты — живут сами по себе, без пятна
│   └── waves/          гребни волн
└── textures/       поверхности — плитки земли, которые грузит рендер
    └── plot_grass/     низкая трава участков построек
```

Группа — это **роль объекта в игре**, а не техника исполнения. Лагерь лесоруба
сделан из тех же примитивов, что и топор, но он постройка: ставится в пятно и
проверяется на зазор. `textures/` — поверхности: это не спрайт и не атлас, а
бесшовная плитка, которую рендер кладёт на землю (участки построек).

`art/tools/` — не группа: там инструменты, которые смотрят на все проекты
сразу. Пока один — **стенд моделей** ([README](tools/model-stand/README.md)):
открывается двойным кликом по `tools/model-stand/index.html`, показывает любую
модель в 3D рядом с кадрами её атласа и говорит, поехала она в игру или нет.
Каталог стенда собирается из репозитория (`python3 tools/model-stand/tools/build_catalog.py`)
и в модели ничего не пишет.

## Как заводить новый проект

1. Определить группу по роли в игре (§ выше).
2. Собрать каркас — [docs/STRUCTURE.md §4](../docs/STRUCTURE.md): `tools/`,
   `out/`, `renders/`, `README.md`.
3. Загрузить скиллы: `4tox-lowpoly-3d` (стиль и палитра), `4tox-house-3d`
   (если постройка), `4tox-building-forge` (метод сборки). Порядок работы —
   в [docs/PIPELINE.md](../docs/PIPELINE.md).

Каркас нового проекта умеет делать скилл:
`4tox-building-forge/scripts/scaffold.py`.

## Что помнить

* **Форма собирается только в живом Blender** через сокет аддона — см.
  [AGENTS.md](../AGENTS.md). Headless годится лишь для рендера уже
  замороженной геометрии.
* **Геометрия — чистый Python без `bpy`.** Blender только рисует: иначе форму
  не измерить и не повторить.
* **Каждый проект считает корень репозитория сам**, тремя уровнями вверх
  (`REPO = ROOT/../../..`) — абсолютных путей внутрь репозитория нет.
* **Упаковщик пишет прямо в игру**, в `mapgen2/assets/<имя>/`. Шага
  «скопировать руками» быть не должно.
* **В README проекта — числа и раздел «что осталось неидеальным».** Без
  последнего следующий человек примет известный дефект за новый.
