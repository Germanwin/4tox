# Как модель становится спрайтом в игре

Один путь для всех ассетов 4tox: от чистой геометрии до атласа, который грузит
`mapgen2/index.html`. Если делать по шагам, ничего не забывается; если
пропустить — модель останется лежать в `art/` и в игру не поедет.

Раскладку папок см. в [STRUCTURE.md](STRUCTURE.md).

```
art/<группа>/<имя>/tools/<имя>.py      геометрия, чистый Python без bpy
            ↓
        build_live.py + live_config.json    сборка в ЖИВОМ Blender (сокет 9876)
            ↓
        renders/*_raw.png                   сырые кадры Blender
            ↓
        compose.py                          тень, контур, посадка в клетку
            ↓
        out/<тег>_<поворот>.png             спрайты
        out/<тег>_sprites.json              точки опоры и имена кадров
            ↓
        pack_atlas.py / pack_<имя>.py       упаковка
            ↓
mapgen2/assets/<имя>/{atlas.png,atlas.json,atlas.js}    ← ЭТО грузит игра
            ↓
        index.html + js/<имя>.js            подключение
```

---

## Шаг 1. Геометрия — чистый Python

Форма живёт в `tools/<имя>.py` и **не импортирует `bpy`**. Генератор отдаёт
список деталей — имя, семейство, вершины, грани:

```python
def build(variant=None):
    return [dict(name='wall_front', family='plaster', verts=[...], faces=[...]), ...]
```

Зачем так: форму можно измерить, сравнить, повторить и отладить без Blender —
`python3 tools/<имя>.py` печатает габарит, объём, замкнутость и бюджет
треугольников за секунды. Blender тут ни при чём.

## Шаг 2. Сборка в живом Blender

**Правило заказчика: форму собирают только в уже запущенном Blender** через
сокет аддона blender-mcp (`127.0.0.1:9876`). Headless годится только для
рендера **уже замороженной** геометрии. Полностью — в [AGENTS.md](../AGENTS.md).

```bash
PY=/Users/hermmoment/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/python/bin/python3
$PY tools/blmcp.py run tools/build_live.py --config live_4x.json
```

Что рендерить, задаёт `live_config.json` (или `live_<пресет>.json`): варианты,
повороты, `ppu`, разрешение, экспорт. Модель появляется во вьюпорте заказчика
сразу — правки формы идут на глазах, Blender не перезапускается.

Ограничения живого процесса (иначе снесёшь чужой файл) — в
[AGENTS.md](../AGENTS.md): не звать `read_factory_settings`, не сохранять чужой
файл, работать в своей сцене и со своим префиксом имён, сбрасывать кэш модулей.

## Шаг 3. Пост-обработка

`compose.py` превращает сырой рендер в спрайт: кладёт кадр в клетку, рисует
тень по канону, обводит силуэт контуром, обрезает и запоминает точку опоры.

На выходе — `out/<тег>_<поворот>.png` и **манифест** `out/<тег>_sprites.json`.
Манифест — это промежуточный формат между проектом и упаковщиком: имена файлов,
размеры и точки опоры.

```json
{"ppu": 80.0, "res": [512, 640], "frames": {
   "townhall_b_0": {"file": "th_b_0.png", "w": 434, "h": 446,
                    "anchorX": 218.0, "anchorY": 268.0,
                    "variant": "b", "rotation": 0}}}
```

## Шаг 4. Гейт (стиль)

Готовые кадры прогоняют стиль-гейтом — он ловит то, что глазами не поймать:
долю пикселей вне палитры, крупность фасетов, толщину контура, ширину тени.

```bash
$PY3 tools/gate.py                 # у кого есть
python3 ~/.dsh/skills/4tox-lowpoly-3d/scripts/audit.py --kind building <кадры>
```

Канон стиля, палитра и пороги живут в скилле `4tox-lowpoly-3d`, а не здесь:
здесь только ссылка, чтобы не расползались две версии чисел.

## Шаг 5. Упаковка в атлас

Упаковщик читает манифест из `out/` и складывает кадры в три файла в
`mapgen2/assets/<имя>/`. **Пишет прямо в игру** — промежуточного «скопировать
руками» быть не должно.

| Упаковщик | Читает | Пишет |
|---|---|---|
| `mapgen2/tools/pack_townhall.py` | `art/buildings/townhall/out/sprites.json` | `mapgen2/assets/townhall/` |
| `mapgen2/tools/pack_hut_rect.py` | `art/buildings/townhall/out/hutrect_sprites.json` | `mapgen2/assets/hut/` |
| `mapgen2/tools/pack_waves.py` | `art/fx/waves/out/sprites.json` | `mapgen2/assets/waves/` |
| `art/buildings/lumbercamp/tools/pack_lumbercamp.py` | `out/lc_<поворот>.{png,json}` | `mapgen2/assets/lumbercamp/` |
| `art/buildings/villager_house/tools/pack_atlas.py` | `out/vh_sprites.json` | `mapgen2/assets/house/` |
| `art/characters/villager/tools/pack_atlas.py` | `out/vg_sprites.json` | `mapgen2/assets/villager/` |

Три файла — одно и то же разными способами:

| Файл | Зачем |
|---|---|
| `atlas.png` | картинка со всеми кадрами |
| `atlas.json` | метаданные для http-загрузки |
| `atlas.js` | те же метаданные как `window.<ИМЯ>_ATLAS = {…}` |

`atlas.js` существует не для красоты: игра открывается по `file://`, где
`fetch` JSON запрещён. Поэтому метаданные дублируются скриптом.

**Проверка, что упаковщик смотрит туда, куда надо:** после прогона `git status`
должен показать изменение в `mapgen2/assets/<имя>/`. Если изменений нет —
либо атлас уже такой, либо упаковщик читает не то.

## Шаг 6. Подключение в игре

1. В `mapgen2/index.html` — строка `<script src="assets/<имя>/atlas.js"></script>`
   **до** модулей игры (они читают глобальную переменную при загрузке).
2. Загрузчик: свой `js/<имя>.js` по образцу `js/villager.js` (персонаж),
   `js/buildings.js` (постройка в пятно) или `js/waves.js` (эффект).

Как игра читает метаданные:

| Поле | Кто читает | Что делает |
|---|---|---|
| `ppu` | `js/sprites.js`, `js/buildings.js` | пикселей кадра на юнит модели → масштаб спрайта |
| `az_deg`, `el_deg` | там же | азимут и подъём камеры рендера (45°, 35.2644°) |
| `frames[].anchor` / `anchorX,anchorY` | все загрузчики | пиксель кадра, куда проецируется точка опоры |
| `frames[].footprint` | `js/buildings.js` | пятно застройки по повороту (4 × 3 ↔ 3 × 4) |
| `mul` | `js/buildings.js` | крупность; по умолчанию — правило зазора `1 − 2·BASE_MARGIN/длина` |
| `frames[].ground` | `js/buildings.js` | наземный контур в клетках от опоры — по нему постройка встаёт по середине пятна |
| `cell` | `js/hero.js`, `js/villager.js` | размер клетки персонажа (112 × 132) |
| `anims` | `js/hero.js`, `js/villager.js` | список анимаций и кадров в секунду |

Поля `footprint`, `mul` и `ground` — не украшение: без них постройка встанет
«примерно» в пятно, вплотную к краю или не по середине. Требование к посадке —
в [AGENTS.md](../AGENTS.md).

## Приёмка в игре

Последний шаг не «посмотреть глазами», а прогнать приёмку — она ловит то, что
глаз пропускает:

```bash
node mapgen2/tools/place.js       # постройка: зазор до кромок, середина контура
node mapgen2/tools/villager.js    # персонаж: ходьба, рубка, ни шага в воду
node mapgen2/tools/townhall.js    # лист: варианты и повороты на настоящей карте
node mapgen2/tools/smoke.js       # генератор без браузера
```

Кадры складываются в `mapgen2/tools/out/` — это доказательство прогона, в git
оно не идёт.

## Чего в конвейере нет

* **Атласы `sprites/` и `hero/` не воспроизводятся из этого репозитория** —
  унаследованы от прежних проектов (`mapgen/`, затем `atlas3d/`), которых
  больше нет на диске вместе с исходными моделями.
* **Автоматической проверки «атлас не устарел»** нет: если поменять модель и
  забыть про упаковщик, игра покажет старый спрайт и не скажет об этом. Пока
  лечится дисциплиной — шаг 5 обязателен.
