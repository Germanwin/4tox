# Ратуша для mapgen2

Три варианта одного здания — **бедная деревенская ратуша**. Пятно застройки
**4 x 3 клетки** (X — длинная сторона), при повороте на 90° — 3 x 4. Стиль снят
с существующего атласа `mapgen2/assets/sprites/atlas.png`: низкополигональные
фасеты, плоское затенение, тёмный контур по силуэту, приглушённая палитра.

В генераторе карт ратуша уже стоит как слой построек: `mapgen2/js/buildings.js`,
`mapgen2/assets/townhall/` (атлас 3 x 4 кадра) и режим размещения в панели —
см. `mapgen2/README.md`, раздел «Ратуша: постройки на карте».

## Варианты

| Вариант | Что это | Чем отличается силуэт |
|---|---|---|
| **A** | главный дом: обмазанный плетень под двускатной соломой, глухой фонарь с колоколом на коньке | ровный конёк, мелкая надстройка по центру |
| **B** | тот же дом + крыльцо с навесом, плетень по бокам двора, кадка, поленница | приземистый выступ спереди, двор |
| **C** | тот же дом + звонница прямо в щипце (проём, колокол на качалке) | проём в торце, колокол видно с торца |

Все три — одна и та же изба: одинаковые стены, каркас, цоколь, крыша и
соломенная фактура. Отличаются только тем, что деревня пристроила.

## Конвенции (замерены по эталонному атласу)

| Что | Значение | Почему так |
|---|---|---|
| 1 юнит модели | 1 клетка карты | ратуша = 4 x 3 юнита |
| Камера | ортографическая, азимут 45°, подъём **35.264°** (`atan(1/√2)`) | истинная изометрия: квадрат на земле даёт ромб ровно 2:1, как в эталоне |
| Кадр рендера | 512 x 640, орто-масштаб 8.0 → **80 px на юнит** | запас по краям, объект никогда не обрезан |
| Свет | солнце сверху-слева-спереди, направление `(-0.36, 0.30, 0.88)`, энергия 2.05 | верхние грани светлее боковых, тени уходят вправо-вниз — как у дуба и валуна |
| Контур | тёмный `#0e120e`, 1 px расширения (~2 px на 80 ppu) | у растительности в атласе контур есть, у камней нет; дом получил «растительный» |
| Тень | мягкое чёрное пятно под пятном застройки, альфа 0.07 | у крупного здания тень на земле физически прячется за ним самим, поэтому она почти невидима и легко вырезается |
| Повороты | 4 через 90° | как у всех объектов атласа |

### Палитра

Солома `#A8823C` / старая солома `#8E6C2C`, обмазка `#93714A`, каркас `#5E3D1E`,
доски `#A07C4C`, цоколь `#8E9498` и `#6E747A`, мох `#466B34`, проёмы `#1A140E`,
утоптанная земля `#7A6244`.


## Как пересобрать

```bash
# 1. рендер. Живая сессия (правило заказчика: форма — только в запущенном Blender):
PY=/Users/hermmoment/.dsh/profiles/desktop/node_modules/dsh-blender/.venv/bin/python
$PY shovel/tools/blmcp.py run townhall/tools/build_live.py
# пакетно, тем же кодом (для CI и когда сессии нет физически):
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup \
    -P tools/build_townhall.py -- --variants a,b,c --rotations 0,90,180,270

# 2. пост-обработка (PIL есть только в python3 воркспейса, не в Python Blender)
python3 tools/compose.py --variants a,b,c --rotations 0,90,180,270

# 3. листы и проверка
python3 tools/present.py
python3 tools/verify.py
```

Полезные флаги: `--no-outline` (спрайты без контура), `--rotations 0`
(быстрый кадр при правке формы), `--samples 96` (качество рендера).

## Что отдавать в игру

`out/sprites.json` — те же поля, что у атласа mapgen2: `anchorX`/`anchorY`
это пиксель кадра, куда проецируется **центр пятна застройки** (центр ромба
4 x 3). Раскладка по клеткам:

```
      (0,0) --- (1,0) --- (2,0) --- (3,0)        X — длинная сторона
        |         |         |         |          x, y — мировые клетки,
      (0,1) --- (1,1) --- (2,1) --- (3,1)        начало — центр пятна
        |         |         |         |
      (0,2) --- (1,2) --- (2,2) --- (3,2)
```

Чтобы пятно легло ровно в 4 клетки, спрайт ставится **разным масштабом по
осям** — и это главное, что нужно знать при передаче в игру. Пятно 4 x 3
клетки занимает по экрану `4 * (пикселей_на_клетку) / 2` пикселей по X:
клетка карты — ромб 2:1, поэтому шаг клетки по X равен половине ширины ромба.
В кадре рендера те же 4 юнита занимают `4 * cos(45°) * ppu` пикселей. Отсюда

```
scaleX = (4 * клетка / 2) / (4 * cos(az) * ppu) = (клетка / 2) / (cos(az) * ppu)
scaleY = scaleX * sin(30°) / sin(el)            = (клетка / 4) / (sin(el) * cos(az) * ppu)
```

При клетке 64 px, `ppu = 80`, `az = 45°`, `el = 35.2644°` это **0.5657 по X
и 0.4899 по Y** (проверяется в `tools/present.py`). Одинаковый масштаб по
обеим осям — ошибка: у карты вертикаль клетки это `sin(30°) = 0.5`, а у
камеры рендера `sin(35.2644°) = 0.5774`, и основание ратуши уезжает с пятна
на 15 %. Считать «4 клетки = 4 ширины ромба» тоже нельзя: это даёт ровно
вдвое крупный спрайт (так и было в первой версии `out/final_map.png`).

В генераторе карт это делает `mapgen2/js/buildings.js` (`scaleAt`), а спрайты
для него упаковываются в атлас командой `mapgen2/tools/pack_townhall.py`.

## Чего в моделях нет

Дорог, заборов вокруг всего пятна, флагов, часов, каменной кладки «на замок»,
стекла в окнах, черепицы. Ратуша бедной деревни: солома, жерди, обмазка,
булыжник в цоколе, ни одного лишнего украшения.

Утоптанной земли перед входом (настила, который читался выступающим порогом)
в моделях больше нет — снята 2026-10-13 по правилу посадки: всё, что стоит на
земле, должно быть внутри пятна застройки, иначе основание не встанет по его
середине и соседние постройки не поставить рядом (`mapgen2/AGENTS.md`).
Булыжники у входа оставлены: их край (1.91 юнита при пятне 1.5) игра поджимает
вместе со спрайтом, и в клетках они внутри.

# Хижина жителя деревни

Отдельная постройка того же пайплайна: **овальная обмазанная хижина** под
двускатной соломой. Снята с эталонного рендера `ref/ref_full.png` (лежит в
репозитории вместе с листом сверки). Пятно — примерно **2.4 x 2.2 юнита**.

| Что | Как сделано |
|---|---|
| Стена | овальная в плане (15 сегментов, 5 рядов), фасеты красятся тремя тонами обмазки, вершины дрожат — «глина» читается пятнами, как на эталоне |
| Каркас | столбы через каждые три сегмента овала, венец по верху стены, земляная завалинка по низу |
| Крыша | конёк **вдоль Y**: остов собирается с коньком по X и поворачивается на 90°, тогда скат уходит вправо-вниз, а торец с дверью смотрит влево-вперёд — как на эталоне. Дранки вдоль ската (23 на скат, три тона), коньковый брус с торчащими концами, тёсовая обвязка торцов |
| Дверь | ставится уже в конечной системе по углу 145° овала: две стойки, перекладина, тёмный проём, полог из шкуры |
| Пропорции | подобраны перебором (`tools/hut_sweep.py` + `ref/score.py`), а не на глаз: стена 2.16 x 2.36, полудлина конька 1.26, полупролёт ската 1.34, низ ската 1.23, конёк 2.50 (скат ~42°). Лучший вариант из 40 — по сумме трёх IoU с эталоном: силуэт 0.841, солома 0.417, стена 0.521 |
| Палитра | обмазка `#D07C2C`, солома `#BE8428`, каркас `#413327`, шкура `#B6B0A2`. Краснота обмазки подобрана по **рендеру**: стена выходит `#987850` (эталон `#A07850`), солома `#C0A870` (эталон `#C0A870`) |

Камера, свет, контур и тень — общие с ратушей (`thpipe.py`, `geom.py`),
поэтому хижина встаёт в один ряд с остальными спрайтами атласа.

```
townhall/
  tools/hut.py           геометрия хижины (размеры, палитра, детали)
  tools/build_hut.py     рендер: blender -b -P ... -> renders/hut_<поворот>_raw.png
  tools/compose_hut.py   пост-обработка: тень, контур, обрезка -> out/hut_<поворот>.png
  hut.blend              готовая сцена Blender (поворот 0)
  ref/                   эталон, сетка разметки и лист сверки
```

```bash
# рендер (нужен --factory-startup)
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup \
    -P tools/build_hut.py -- --rotations 0,90,180,270 --save-blend

# пост-обработка
python3 tools/compose_hut.py --rotations 0,90,180,270

# лист сверки с эталоном
python3 ref/compare.py out/hut_0.png ref/compare.png
```

Замер эталона даёт направление дранок ≈52° по экрану, отсюда скат ≈30° и
вытянутый в плане овал. Референс снят **зеркально** относительно камеры
пайплайна (`az = 45°`), поэтому в листе сверки рендер показан и как есть,
и отражённым: композиция «конёк вверх-вправо, дранки вниз-вправо, дверь
слева» у неотражённого рендера уже совпадает с эталоном.
