# REPRO.md — как повторить каждый сценарий

Всё, что здесь описано, выполнено на одной машине и записано в `runs/`.
Команды предполагают, что пакет распакован, а рядом лежит репозиторий 4tox на
коммите `6b9f06b` (для baseline — на `dc75820`).

## 0. Окружение замеров

| что | значение | откуда |
|---|---|---|
| машина | MacBook Air `Mac16,13`, Apple M4, 10 ядер (4P+6E), 16 ГБ | `scenario.json → cpu/cores/memGB` |
| ОС | macOS 15.7.3 (Darwin 24.6.0) | там же |
| браузер | Google Chrome 156.0.8078.48 | `scenario.json → chrome` |
| режим браузера | `--headless=new` (объяснение ниже) | `scenario.json → headless` |
| Node | v24.12.0 | `scenario.json → node` |
| окно | 700 × 773 CSS, `devicePixelRatio = 2`, канвас 1400 × 1546 | `scenario.json → observed.*.canvas` |
| карта | 192 × 192, сид `каменная-согра-581` (в мультиплеере) | `scenario.json → start` |
| население на старте | 2 деревни × 3 жителя = 6, 6 построек | там же |
| сервер | локальный `game/server/server.js --port N --no-upnp` под предзагрузкой `tools/deterministic-random.js` | `run.log` |

**Почему headless.** Окно на экране забирает фокус у человека за машиной, а
прогон длится час. Проверено (и это часть паспорта), что `--headless=new`
воспроизводит ровно те механизмы, которые здесь измеряются:

- два независимых браузера дают по одному видимому окну каждый —
  `document.visibilityState = 'visible'`, rAF 60 кадров/с;
- скрытая вкладка в общем окне — `hidden`, **0 кадров rAF за 60 с**, таймер
  200 мс редеет до 1 раза в секунду (замер `tools/` проверочным скриптом,
  повторено в `runs/S3`);
- переключение вкладки меняет эти состояния мгновенно.

Чего headless не воспроизводит — композицию кадра на GPU и реальный FPS окна.
Поэтому **FPS в `runs/` — это FPS главного потока и канваса, а не окна с GPU**;
см. `LIMITATIONS.md`.

**Почему детерминированный сервер.** Сид партии выбирается случайно
(`server.js:randomSeed`). Чтобы все прогоны получили один остров, сервер
запускается с предзагрузкой `-r tools/deterministic-random.js`, которая
подменяет `Math.random` LCG с фиксированным началом. **Исходники игры при этом
не меняются** — файл `game/server/server.js` остаётся байт в байт коммитным.

## 1. Общая команда

```bash
cd <пакет>
node tools/run-scenario.js --scenario S3 --repo /путь/к/4tox \
     --out runs/S3/r1 --warmup 25 --measure 60
```

Все сценарии по три повтора:

```bash
REPO=/путь/к/4tox tools/run-all.sh runs
# только мультиплеер: SCENARIOS="S2 S3 S4" tools/run-all.sh runs
# только S1 с тем же сидом, что в сети: SEED="каменная-согра-581" \
#   SCENARIOS=S1 tools/run-all.sh runs
```

Разбор — после прогонов:

```bash
node tools/analyze.js runs      # пишет runs/summary.md и summary.json
```

## 2. Сценарии

### S1 — одиночная партия, одна видимая вкладка

```bash
node tools/run-scenario.js --scenario S1 --repo <repo> \
  --out runs/S1/r1 --warmup 25 --measure 60 --seed "каменная-согра-581" --size 192
```

- **Условия:** одна страница, `visible`, rAF 60/с, сеть не участвует.
- **Население:** одна деревня (3 жителя, 3 постройки) — одиночная партия по
  определению; для сравнения с сетью по населению это надо помнить.
- **Что отличает:** базовая стоимость мира и отрисовки без сети.
- **Ожидаемо хорошо:** `simPerReal ≈ 1.0`, rAF 60, `frameOver33` близко к нулю.

### S2 — хост и гость на одном ПК, два видимых окна, localhost

```bash
node tools/run-scenario.js --scenario S2 --repo <repo> --out runs/S2/r1
```

- **Условия:** ДВА отдельных браузера (два окна), оба `visible`, оба рисуют
  60 кадров/с. Проверяется до измерения (`scenario.json → observed`), при
  несовпадении прогон падает.
- **Что отличает:** локальная сеть и конкуренция CPU/GPU без скрытого хоста.
- **Ожидаемо:** хост шлёт ~12 снимков/с (интервал 80–85 мс), гость применяет
  столько же, сглаживание включено (smooth=1) на всех снимках.

### S3 — хост и гость соседними вкладками, активна вкладка ГОСТЯ

```bash
node tools/run-scenario.js --scenario S3 --repo <repo> --out runs/S3/r1
```

- **Условия:** один браузер, две вкладки одного окна; после старта
  вызывается `Page.bringToFront` для гостя и больше вкладки не переключаются.
  Хост `hidden`, гость `visible`. Проверяется до измерения.
- **Что отличает:** браузерное троттлинг-поведение скрытого хоста.
- **Признак сбоя:** интервал применения снимка у гостя ≈ 1000 мс, при
  `NET_INTERVAL = 80 мс`; rAF хоста = 0 кадров; на экране гостя житель стоит
  ~930 мс из каждой секунды и прыгает.
- **Наблюдение:** примерно через 30–50 с после начала измерения страница
  хоста перестаёт выполняться (3/3 прогона), и снимков не становится вовсе.
  Это отдельное наблюдение, причина не установлена — `runs/S3/README.md`.
  Если нужно измерить только «1/с», смотрите `early` в `summary.json`.
- **Это и есть сценарий жалобы** «гость в соседней вкладке, движение рывками».

### S4 — те же вкладки, активна вкладка ХОСТА

```bash
node tools/run-scenario.js --scenario S4 --repo <repo> --out runs/S4/r1
```

- **Условия:** гость `hidden`. У гостя rAF не идёт вовсе — он не рисует.
- **Что отличает:** обратное направление; показывает, что «гость скрыт» — это
  не «гость медленно получает», а «гость не рисует», и что при возврате
  вкладки сглаживание включается не сразу (`netLastTick < 300 мс`).

### S5 — тот же ПК, два видимых окна, но через VPS

```bash
PROD_URL=https://374412.fornex.cloud/game/ \
  node tools/run-scenario.js --scenario S5 --repo <repo> \
  --url "$PROD_URL" --out runs/S5/r1
```

- **Условия:** как S2, но обе страницы открыты с прод-адреса, сервер — VPS
  (`/opt/4tox/COMMIT = 1d842c4`), канал — настоящий интернет.
- **Чего нельзя:** сид на проде задать нельзя (сервер выбирает случайно) —
  он записывается в `scenario.json → start.seed` и отличается от S1–S4.
- **Что отличает:** вклад VPS, HTTPS, gzip на реальном канале, RTT.

### S6 — хост и гость на разных устройствах

**NOT RUN.** Второго устройства нет. Команда, которой это делается, —
`tools/run-scenario.js --scenario S5 --url <адрес хоста>` на втором
компьютере; подробности и что именно надо записать — `LIMITATIONS.md`.

## 3. Трасса телепортаций (10–20 с)

Отдельного прогона не нужно: обвязка уже пишет покадровую трассу выбранного
жителя.

- Житель выбирается автоматически: `__passport.pickMover()` — тот, у кого
  расхождение «нарисован / у хоста» самое большое.
- На кадре пишется: время (performance.now), `seq` последнего снимка,
  `Play.state.seconds`, `x/y` нарисованного жителя, `_netTX/_netTY` — цель из
  снимка, число жителей, признак скрытой вкладки.
- На каждом применённом снимке: время, `seq`, время хоста `snap.t`,
  включено ли сглаживание, длительность `Serialize.apply`.

Читать так: в `guest.json` взять `frames` (9 колонок:
`t, seq, simSec, x, y, tx, ty, nVillagers, hidden`) и `applies`
(`t, seq, hostT, smooth, ms`). Пример разбора — `tools/analyze.js`,
поле `motion`.

Короткое окно 10–20 с получается само: `--warmup 20 --measure 15` даёт
15-секундную трассу, а `marks` сохраняют границу окна.

## 4. Что менять нельзя, чтобы числа остались сравнимыми

- Не переключать вкладки во время измерения (кроме момента, заданного
  сценарием, — он записан в `run.log`).
- Не запускать два прогона одновременно: они делят CPU и GPU.
- Не менять `--warmup`, `--measure`, `--size`, окно и DPR между версиями.
- Для сравнения с baseline (`dc75820`) — те же команды, тот же `REPO`
  (распакованная копия `git archive dc75820`), тот же `tools/probe.js`.
