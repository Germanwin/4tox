### BUG-05-01 · Деревни разных игроков ставятся без учёта друг друга: постройки занимают одни клетки · critical

- Файл: `mapgen2/js/session.js:695`, `:708`, `:798`, `:807`
  (+ `mapgen2/js/buildings.js:2171` `villageAt`, `:2119` `neighbourSpot`,
  `:1862` `findSpot`, `:1372-1375` `canPlace`; `mapgen2/js/worldgen.js:898`)

- Что происходит / Почему баг.
  `Session.startMultiCore` и `Session.startBotCore` ставят каждую деревню
  вызовом `Buildings.villageAt(world, sites[i], HOME, VILLAGE, SITE)`. Внутри
  `villageAt` (`buildings.js:2171-2192`) заводит **свой пустой** `list`,
  кладёт в него ратушу и передаёт в `neighbourSpot`/`findSpot` только его:
  `canPlace(world, list, b, place)`. Постройки уже поставленных деревень в этот
  список не попадают никогда — `startMultiCore` собирает `all` лишь ПОСЛЕ
  цикла (`session.js:807`), а `startBotCore` вообще не передаёт `playerList`
  второй деревне. Поэтому «постройка не пересекает другую» проверяется только
  внутри одной деревни.
  `spawnSites` этого не закрывает: минимальная дистанция между площадками —
  `max(12, islandSize*0.15)` клеток (`worldgen.js:898`), а деревня игрока
  (ратуша + дом + лагерь + казарма + лагерь воинов) занимает по габариту
  14–18 клеток, и `neighbourSpot` может увести постройку на `reach+2` клеток от
  габарита (`buildings.js:2119-2123`). То есть площадки формально разнесены, а
  пятна встречаются.

- Репро.

  и для бота: `seed:'scan-181', size:64`, `Session.startBotCore(w)`.

  было, но правило от этого не меняется: проверки просто нет.

- Какая приёмка НЕ ловит.
  `mapgen2/tools/place.js` проверяет «пятна построек не пересекаются» только
  для одиночной деревни (`vlg.overlap`, 530-548); `game/tools/menu.js` играет
  одиночную партию и подкладывает чужого жителя руками (1022-1055), а не вторую

- Уверенность: высокая. Это не «редкий сид», а отсутствующая проверка:

  `{avoid: playerList}` для второй деревни. Заодно `settle` новой деревни
  перестанет выкашивать двор чужой. Проверка: 300 сидов × 2–4 игрока и
  300 сидов бота — ноль `overlaps` между городами; плюс строка в `mp.js`

### BUG-05-02 · В сети (protocol 4) кнопка «Двигать» закрывает правку, а не берёт дом; негодный перенос уходит на сервер · major

- Файл: `game/js/play.js:3283-3315` (ветка клиента), особенно `:3311-3312`
  (`else { editClose(); }`) и `:3314`; сравнить с локальной веткой `:3317`
  (`if (action === 'move') return editMove(null);`); `game/js/hud.js:302-306`
  (навешивание кнопок), `:2246-2247` (`canMove`).
  `game/js/play.js:745` — `startServerNet` ставит `state.netRole = 'client'`
  КАЖДОМУ браузеру протокола 4.

- Что происходит / Почему баг.
  В live-сети protocol 4 (`startNet` → `startServerNet`, `play.js:1002-1004`)
  все игроки — клиенты, значит `editAction` всегда идёт в ветку
  `state.netRole === 'client'` (`:3283`). В ней обработаны `rotate`, `delete`,
  `place`, `apply`, `cancel`, а **`move` попадает в `else { editClose(); }`**
  и возвращает `{ ok: action !== 'move', reason: '' }` — то есть `ok:false` с
  ПУСТОЙ причиной. HUD (`hud.js:2209-2215`) показывает тост только при
  непустом `reason`, поэтому нажатие на «Двигать» просто убирает полосу правки
  и ничего не сообщает. При этом `editMove` — чисто локальное состояние
  (`mode = 'move'` + `editFollow`), и на клиенте оно работает: жест удержания
  ЛКМ берёт дом и на отпускании шлёт команду `edit/move` (`:4395-4397` →
  `:3295-3297`). То есть кнопка «Двигать» в MP — единственная из пяти, которая
  не делает того, что написано, а способ «взять дом» остаётся только скрытый
  (полсекунды удержания).
  Второй симптом той же ветки: `place` (`:3295-3297`) отправляет команду
  `edit/move` **без проверки `e.valid`** (в отличие от `apply`, `:3302`), хотя
  `recheck()` уже посчитал ответ движка. На клиенте дом, брошенный в воду или
  на чужое пятно, уезжает на сервер заведомо отклоняемым переносом: игрок видит
  дом в воде до снимка и запись об отказе в журнале (всплывашек в сети нет по
  правилу 2026-10-24). Локальный путь в том же месте отказывает словами
  (`editAction('apply')` → `!e.valid`), то есть поведения два.

- Репро.
  1) Сеть protocol 4, два браузера, гость: удержать ЛКМ на своём доме →
     полоса правки открыта → нажать «Двигать».
     Ожидалось: дом идёт за курсором (`mode:'move'`, как в одиночной).
     Фактически: полоса исчезает, дом стоит; в `Play.state.edit` — `null`.
  2) Гость: взять дом удержанием и отпустить над водой.
     Ожидалось: отказ словами движка, дом остаётся на месте (как в соло).
     Фактически: уходит `{type:'edit',action:'move'}`, сервер отвечает
     `invalid_place`, дом прыгает обратно на снимке.

- Доказательство (код 6 строк).
  ```js
  // game/js/play.js:3308-3314
        } else if (action === 'cancel') {
          B.restore(state.world, b, e.orig);
          editClose();
        } else {                       // <-- сюда падает action === 'move'
          editClose();
        }
        return { ok: action !== 'move', reason: '' };   // ok:false, reason:''
  ```
  ```js
  // game/js/hud.js:306  — кнопка зовёт это без проверки aria-disabled
  btn.addEventListener('click', function () { editAct(pair[1]); });
  // hud.js:2213  if (res && !res.ok && res.reason) toast(res.reason);  -> молчит
  ```

- Какая приёмка НЕ ловит. `game/tools/mp.js` не содержит ни одного упоминания
  правки (`edit`, `правк`, `Повернуть`, `Двигать`, `rotate` — grep пуст), а
  `game/tools/menu.js` проверяет «Двигать» и правку только в одиночной партии
  (`14. правка постройки`, 1633+). `mapgen2/tools/*` играют без сети. Юнит-тест
  `game/tools/tests/mp-commands.test.js` («edit: владение, перенос, поворот и
  снос», 5/5 зелёные) проверяет только серверный `Commands.edit`, а не ветку
  браузера `editAction`.

- Уверенность: высокая по коду (ветка читается однозначно), средняя по живому
  прогону: браузер не запускал, `Play` без DOM не поднимается. Проверяется
  одной строкой в `mp.js`: гость открывает правку, жмёт `#editMove`, ждёт
  `Play.state.edit.mode === 'move'`.

- Правка.
  ```js
  // play.js, до ветки клиента (как в локальной):
  if (action === 'move') return editMove(null);
  // и в ветке клиента для 'place':
  if (!e.valid) return { ok: false, reason: e.reason };
  ```
  `editMove` не касается мира, поэтому серверу ничего не нужно; перенос
  по-прежнему уходит одной командой на отпускании/«Применить».

### BUG-05-03 · Снос дома не выселяет жильцов: `v.home` остаётся на снесённой постройке · minor

- Файл: `mapgen2/js/buildings.js:1777-1785` (`remove`),
  `:1790-1819` (`releaseWorkers` — только `employer`/ученики);
  `mapgen2/js/session.js:994-1001` (`residentsOf` — считает по `v.home`);
  `mapgen2/js/villager.js:2162-2175` (якорь прогулки берётся у дома при
  создании).

- Что происходит / Почему баг.
  `Buildings.remove` освобождает рабочих и учеников, но не жильцов дома:

- Репро.

### BUG-05-04 · Военный лагерь, разрушенный боем, нельзя убрать: 25 клеток заняты навсегда · minor

- Файл: `mapgen2/js/buildings.js:201` (`EDIT.warcamp.remove = false`),
  `:1825-1852` (`ruin` — оставляет завал в списке),
  `:1372-1375` (`canPlace` считает завал обычной постройкой),
  `:215-219` (`canEdit` не смотрит на `rubble`);
  `mapgen2/js/villager.js:550-557` (`blockedMap` метит клетки завала
  непроходимыми).

- Что происходит / Почему баг.
  Лагерь воинов — единственная постройка с HP (`combat.js:44` — 40), которую
  игрок не может снести (`EDIT.warcamp.remove = false`, причина «в нём живёт
  дружина»). Но `ruin()` от боя ставит `rubble = true` и оставляет объект в
  списке, а `EDIT`/`canEdit` про завал не знают: снести завал тоже нельзя
  («военный лагерь снести нельзя»), хотя дружины там уже нет (`ruin` снимает
  `v.warcamp`). Итог: пятно 5×5 остаётся занятым навсегда — `canPlace` на нём
  говорит «тут уже стоит постройка», `blockedMap` держит 25 клеток
  непроходимыми. Игрок теряет место в собственной деревне и не может поставить
  новый лагерь туда. Та же дыра теоретически у ратуши, но падение ратуши
  заканчивает партию, а лагерь — нет.

- Репро.
  ```js
  node -e "const g=require('./game/tools/tests/load-engine.js').loadEngine();
  const w=g.WorldGen.generate({seed:'bot-0',size:64}); const st=g.Session.startBotCore(w);
  const c=st.botTown.buildings.find(b=>g.Buildings.typeOf(b)==='warcamp');
  g.Buildings.ruin(w,c,{villagers:st.villagers});
  console.log(g.Buildings.canEdit(c,'remove'), g.Buildings.remove(w,st.buildings,c,{villagers:st.villagers}),
    st.buildings.indexOf(c)>=0, g.Buildings.cells(c).length);"
  ```

- Доказательство (вывод).
  ```
  after ruin: canEdit remove {"ok":false,"reason":"военный лагерь снести нельзя"} rubble true
  remove -> {"ok":false,...,"removed":0}   still in list true   cells 25
  canPlace новой казармы на это пятно -> false, 'тут уже стоит постройка'
  ```

- Какая приёмка НЕ ловит. `place.js`/`menu.js` сносят только живые постройки;
  `combat.js`-приёмки проверяют падение ратуши, а не разбор завала лагеря.

- Уверенность: высокая (вывод выше). Оценка «навсегда» — по коду: другого
  способа убрать объект из `state.buildings` в браузерной версии нет.

- Правка. Одна строка в `canEdit`: завал можно убирать независимо от типа —
  `if (b.rubble && action === 'remove') return { ok: true, reason: '' };`
  (и в `EDIT_NO` ничего не менять). Либо в `ruin()` для `warcamp` ставить
  `remove`-разрешение на самом завале. Заодно `canPlace` перестанет считать
  завалы «постройкой» только если их разрешено убирать — иначе мир получит
  вторую постройку в тех же клетках.

### BUG-05-05 · `canPlace` не проверяет собственные выходы: дом с дверью в воду покупается за 12 брёвен · minor

- Файл: `mapgen2/js/buildings.js:1348-1415` (`canPlace` — проверяются только
  клетки пятна, помехи, жители и выходы СОСЕДЕЙ),
  `:2037-2044` (`frontSpot`), `:1287-1315` (`sealedExits` — только чужие
  выходы и `self` при правке).

- Что происходит / Почему баг.
  Правило 2026-10-26 требует «не запирать выходы», но проверка устроена
  асимметрично: у НОВОЙ постройки её собственные выходы не считаются. `frontSpot`
  для дома/ратуши — клетка сразу за передней кромкой, и она может быть водой,
  песком у кромки или чужой стеной: `canPlace` смотрит только `world.tile`
  пятна, а не клетку двери. Призрак при этом зелёный, постановка списывает
  брёвна. Практическое следствие: дом, у которого дверь в море (и вокруг двери
  нет суши в радиусе 2 — коса, мыс), не может родить жителя: `birthAttempt`
  ищет `spawnSpot(…, BIRTH_REACH=2)` от двери и, не найдя, помечает дом
  «двери заняты»; сам дом при этом числится жильём. У лагеря хуже: его 7 мест
  двора подхода (`yardPoints`) не проверяются вовсе, и лагерь, у которого все
  клетки подхода в воде/под соседом, остаётся без работы, хотя игрок заплатил
  20 брёвен (в панели потом «нет пути»).

- Репро.
  ```js
  // синтетическая коса: x<=12 — трава, дальше вода; дом rot 90, пятно 3x2 в x10..12
  node -e "const g=require('./game/tools/tests/load-engine.js').loadEngine();
  ... canPlace(w,[b],b,{clearable:false,requireClear:true,yard:1}) ..."
  ```

- Доказательство (вывод).
  ```
  fp {"w":3,"h":2}  canPlace on shore true  'место свободно'
  frontSpot {"x":13,"y":5} isLand 0          // дверь в воде, место «годится»
  own exits 8                                 // кольцо целиком, поэтому и «запертых» нет
  spawnVillagersCore: жители сели на сушу (12.5,6.5/7.5/8.5) — create ищет место
  ```

- Какая приёмка НЕ ловит. `place.js` проверяет «в воде призрак запрещён»
  (`:858`) по клеткам ПЯТНА, а не двери; правило выходов проверяется только на
  чужой постройке (`regress.js:711-736`).

- Уверенность: высокая по механике (проверки просто нет); оценка вреда —
  средняя: в стартовой деревне такие места не выпадают (120 сидов — ни одного),
  это ручная постановка на берегу.

- Правка. В конце `canPlace`, рядом с проверкой жителей:
  ```js
  var f = frontSpot(b, 1);
  if (inWorld(world, f.x, f.y) && !exitFree(world, occupancy(world, afterList), f.x, f.y)) {
     /* не отказ, а предупреждение: у дома это «двор в воде», у лагеря — место подхода */
  }
  ```
  Решение по строгости — за заказчиком: либо `ok=false` с фразой «дверь в
  воду», либо `res.reason` предупреждением (как кольцо двора). Минимум —
  проверить клетки подхода `yardPoints(b)` у лагеря и не брать деньги за
  постройку, в которую нельзя войти.

## Проверено и НЕ баг

- **Пятна и посадка.** `footprints`/`FALLBACK_FP` совпадают с атласами:
  ратуша 4×3 (90° 3×4), дом 2×3 (90° 3×2), лагерь 3×3, казарма 4×3 (90° 3×4),
  лагерь воинов 5×5 во всех поворотах. `mul` в атласах = `siteMul` = 0.7667 /
  0.7156 / 0.7973; `BASE_MARGIN`/`MARGIN_K` по правилу 2026-10-13/14.
  `atlas.js` и `atlas.json` у всех пяти типов совпадают (сравнил поля).
- **Перед вправо-вниз.** `FACE_ROT = 90`, `faceDir(90) = +X`, `frontSpot`
  выходит за переднюю кромку, а не за заднюю; разбор в шапке `buildings.js`
  соответствует кадрам атласа. Это правило, не баг.
- **Двор лагеря.** `yardPoints` на всех четырёх поворотах даёт 7 мест (3 front,
  2 right, 1 back, 1 left), каждое — ровно `YARD_IN = 1/3` от своей кромки,
  `place` внутри пятна, `cell` — снаружи; дублей нет, `workSpotCells` не теряет
  стороны (`sideData`). Заступ 1/3 — правило заказчика 2026-10-17.
- **Военный лагерь.** `modelCells` — 2×2 по центру, `patrolCells` — 21 клетка,
  `cells` — 25 для посадки; `WARCAMP_CAP = 20`, `BARRACKS_YARD_CAP = 10`,
  `TRAIN.barracks = 3`, `WORK.lumbercamp = 3`, `HOUSING.house = 4` — все числа
  совпадают с AGENTS.md и README. `EDIT.warcamp.remove = false` и
  `EDIT.townhall.remove = false` с готовой фразой — намеренное правило.
- **Кусты/трава и «мелочь под зданием».** `obstacle` = дерево/камень крупнее
  гальки, `decor` — всё остальное; в строгом режиме (`requireClear`) куст
  пятно не портит, `settle`/`crushDecor` мнут только декор, деревья не
  трогают; `coverMask` включает пятно+YARD, призрак и pending — правило
  2026-10-17/18 держится.
- **Цены и списание.** `Play.BUILD_MENU` 12/20/28/24 и
  `Commands.PRICE_FALLBACK` 12/20/28/24 совпадают; `GameplayConfig` цен не
  содержит, значит сервер всегда берёт fallback — расхождения нет.
  `Commands.build` списывает ровно `price` и только после `canPlace`,
  `buildLine` — `items.length * price` после успешного плана (юнит-тест
  `mp-commands.test.js` + мой прогон: 100 → 88 → 60 и 0 при отказе).
  Отрицательного баланса нет: `(town.logs||0) < price` стоит до вычитания, а
  команды одного тика идут последовательно. Обхода цены клиентом нет: `owner`
  ставит сервер по токену (`room-runtime.js:336-352`), тип/поворот/
  координаты/длина серии проверяются (`commands.js:152-215`), неизвестный тип
  даёт `price = 0` → `unknown_building`, `x/y` за картой → «край карты».
- **Атомарность серии.** `planLine` ничего не меняет и проверяет каждого
  кандидата против `list.concat(accepted)`; `Commands.buildLine` сначала
  проверяет ВСЕ места (`buildOne`), потом списывает и вставляет — частичной
  серии не бывает. Шаг серии считается по ПОВЁРНУТОМУ пятну (дом rot 0 — 3 по
  X, rot 90 — 4), зазор 1 клетка — правило мира.
- **`checkAt` (правка) и выходы.** До/после передаются парой (`beforeList` /
  `afterList`), `self` защищён от самозапирания, соседи — через `nearRect`;
  `clearable:false, requireClear:true, yard:0` — правила правки жёстче
  постановки, и кольцо двора только предупреждение. «Откат» идёт через
  `restore(snapshot)` (тип/вариант/поворот/место/владелец/hp/rubble).
- **`rebalanceGarrison`.** Зовётся после постройки лагеря и на сервере
  (`commands.js:126-130`), и локально (`play.js:2026-2028`, `:2067-2069`).
  `destinationFor` учитывает и лагеря (20), и дворы казарм (10); «застрявший»
  `v.station`/`v.warcamp` на снесённую постройку лечится в `villager.js`
  (`:3641-3680`), поэтому снос казармы без `rebalanceGarrison` не оставляет
  воина в стене — это проверено кодом, не прогоном.
- **Старт одиночной деревни.** 120 сидов (64 и 96): всегда 3 постройки
  (ратуша/дом/лагерь, военного лагеря нет — правило 2026-10-23), пятна не
  пересекаются, все клетки трава, клетка перед дверью — суша, выходы > 0,
  поворот 90 у всех, житель выходит из дома.
- **«Против деревни».** `startBotCore`: 12 построек (3 игрока + 9 врага:
  ратуша, 2 лагеря, казарма, лагерь воинов `variant:'x'`, 4 дома), 16 жителей
  врага + 3 игрока, ровно 10 воинов и 6 лесорубов, 4 дома = 16 мест — состав
  сходится с требованием 2026-10-23. Fallback при `sites.length < 2` — в
  одиночную партию, без исключения.
- **Лимиты.** `armyRoom` = свободные места лагерей + дворов; `canTrain`
  отказывает «военный лагерь и двор казармы заполнены»; `trainingSlots` = 3;
  `garrisonCells` берёт 10 ближайших к двери клеток кольца.
- **Казарма-вход.** `entrance` считает дверь в осях модели × `mul` и шагает по
  `faceDir`, пока не выйдет из пятна; `in` внутри, `out` снаружи на всех
  четырёх поворотах — соответствует правилу 2026-10-22.
- **`remove`.** Сносит только из списка, освобождает работников (`Session.fire`)
  и учеников (`releaseTrainees`), возврата брёвен нет — возврат нигде не
  обещан (README §«правка»), это правило, а не баг.
- **Наблюдение без последствий:** `Commands.edit` проверяет `canEdit` для
  `rotate` и `delete`, но не для `move`; сейчас `move: true` у всех пяти типов,
  поэтому поведение не отличается. Если появится тип с `move:false`, разница
  выстрелит — стоит дописать проверку заранее (не баг сегодня).
- **Наблюдение без последствий:** `lineInfo().logs` отдаёт `villageLogs()`, а
  не `availableLogs()`; HUD это поле в полосе серии не показывает (берёт
  `price`/`cost`/`afford`), так что лжи на экране нет.

## Топ-5

1. **BUG-05-01 (critical).** `startMultiCore`/`startBotCore` ставят деревни
   независимо: `villageAt` знает только свой список. В 6 % сидов бота постройки
   врага занимают клетки игрока, включая лагерь воинов на ратуше и воина,
   стоящего внутри неё. Лечение — `opts.avoid` в `villageAt` и накопленный
   список в `session.js`.
2. **BUG-05-02 (major).** В сети protocol 4 кнопка «Двигать» закрывает правку
   (`editAction('move')` → `else editClose()`), а негодный перенос у клиента
   уходит на сервер без проверки `e.valid`. Ни `mp.js`, ни `menu.js` этого
   пути не касаются.
3. **BUG-05-03 (minor).** Снос дома не выселяет жильцов: `v.home` и якорь
   прогулки остаются у снесённой постройки, `residentsOf` считает их жильцами
   несуществующего дома.
4. **BUG-05-04 (minor).** Разрушенный боем военный лагерь нельзя убрать
   (`EDIT.warcamp.remove = false` без исключения для завала): 25 клеток
   заняты навсегда, новую постройку туда не поставить.
5. **BUG-05-05 (minor).** `canPlace` не проверяет собственные выходы: дом с
   дверью в воду покупается за 12 брёвен, у лагеря не проверяются клетки
   подхода двора (20 брёвен за лагерь, куда не войти).
