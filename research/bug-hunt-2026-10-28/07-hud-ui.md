### BUG-07-01 · «Новый остров» в сетевой партии открывает главное меню поверх новой игры · major

- **Файл:** `game/js/boot.js:137-153` (`newIsland`), `game/js/lobby.js:146-151`
  (`close`), `game/js/boot.js:155-174` (для сравнения — `toMenu`).
- **Что происходит.** В сетевой партии «Меню → Новый остров» должно выйти из
  комнаты и начать одиночный остров (так записано в комментарии
  `newIsland`: «В сети — это выйти из комнаты и начать одиночную»). Фактически
  выходят из комнаты, **показывают главное меню** и только потом стартуют мир:

  ```js
  // boot.js:143-151
  if (wasNet) {
    if (global.Net) global.Net.leave();
    Play.stopNet();
    if (global.Lobby) global.Lobby.close();   // <-- close() зовёт Menu.show()
  }
  Play.start({ seed: seed, size: size, mode: ... });
  Hud.show();                                  // HUD под меню (z-index 4 < 5)
  ```

  ```js
  // lobby.js:146-151
  function close() {
    stopPolling();
    if (el.screen) el.screen.classList.add('hidden');
    global.Net.leave();
    if (global.Menu && global.Menu.show) global.Menu.show();  // <-- меню
  }
  ```

  `newIsland` не зовёт `Menu.leave()`/`Menu.hide()` и не использует
  `Lobby.enterGame()` (тот скрывает экран лобби без меню). Игрок видит главное
  меню, слышит всплывашку «Новый остров: …» (она `z-index: 6`, выше меню) и не
  видит ни нового острова, ни HUD. Нажатие «Играть» запускает **второй** мир,
  уже с уходом меню.
- **Репро (реальная сеть):** создать лобби, начать игру, Esc → доска «Меню» →
  «Новый остров». Меню остаётся на экране; под ним уже стоит новый остров.
- **Репро (без сервера, ветка кода та же):**
  `Play.state.netRole='host'; __game.newIsland();` → `Menu.isOpen() === true`,
  `#menu` без `hidden`, `#hud` без `hidden`, `Play.state.world` уже новый,
  `netRole === null`.
- **Доказательство (проба):**

  ```
  netNewIsland: { menuOpen: true, menuHidden: false, hudHidden: false,
                  world: true, netRole: null }
  netNewIslandAfter (через 300 мс): { menuOpen: true, menuHidden: false,
                                      hudHidden: false }
  ```

  Приёмка НЕ ловит: `menu.js:1558-1583` проверяет «Новый остров» только в
  одиночной партии; `mp.js` эту кнопку не трогает вовсе.
- **Уверенность:** высокая (ветка `wasNet` проверена в браузере; сервер для
  неё не нужен).
- **Правка:** в `newIsland` вместо `Lobby.close()` звать
  `Lobby.enterGame()` (он делает `stopPolling()` + скрывает экран и не зовёт
  `Menu.show()`), либо сразу после `Lobby.close()` добавить `Menu.hide()`.
  Заодно уйдёт двойной `Net.leave()` (`boot.js:146` + `lobby.js:149`).

### BUG-07-02 · Enter в главном меню запускает игру с прежним выбором, а не активирует кнопку в фокусе · major

- **Файл:** `game/js/menu.js:91-101` (глобальный `keydown`), `game/js/menu.js:106-110`
  (`start`), `game/index.html:429-489` (карточки режима/размера и кубик —
  это `<button>`).
- **Что происходит.** Глобальный обработчик меню ловит `Enter` с `window` и
  сразу зовёт `start()`, а затем `e.preventDefault()`. Если фокус стоит на
  карточке размера, карточке режима или кубике, штатная активация кнопки
  отменяется — вместо неё стартует игра с **текущим** `selected`. Нажатие
  Enter на карточке 128 запускает 96 (или 48/64 — что было выбрано), на
  карточке «Против деревни» — одиночную, на кубике — игру вместо нового сида.

  ```js
  // menu.js:98-100
  var k = global.Keys ? global.Keys.name(e) : String(e.key || '').toLowerCase();
  if (k === 'r') { rollSeed(); e.preventDefault(); }
  else if (k === 'enter') { start(); e.preventDefault(); }   // <-- не смотрит target
  ```

  ```js
  // menu.js:106-109
  function start() {
    if (el.menu.classList.contains('hidden')) return;   // leaving ещё не hidden
    if (selectedMode === 'mp' && actions.mp) { actions.mp(); return; }
    actions.play && actions.play(seed(), selected, { mode: selectedMode });
  }
  ```
- **Репро:** в меню выбрать 96; кликнуть (или Tab) на карточку 128, чтобы она
  получила фокус, но не выбираться; нажать Enter. Мир — 96, карточка 128 так и
  не выбрана. Аналогично Enter на `#dice` стартует партию.
- **Доказательство (проба, фокус на карточке 128, выбрано 96):**

  ```
  enter: { menuOpen: false, selectedCard: 96, worldSize: 96, hudOpen: true }
  ```

  До этого `Menu.select(96)` вызывался программно, карточка 128 получила
  `.focus()`, а `Enter` ушёл через `Input.dispatchKeyEvent`.
  Приёмка НЕ ловит: клавиатурные проверки (`menu.js:3176-3196`) — только `W`/`R`
  на русской раскладке; Enter проверяется лишь как «играть», мышью.
- **Уверенность:** высокая.
- **Правка:** не перехватывать Enter, если событие пришло в элемент управления:

  ```js
  var t = e.target;
  if (k === 'enter' && t && t.closest &&
      t.closest('button, [role="radio"], a, input, select, textarea')) return;
  ```

  Тогда Enter на кнопке делает её штатное действие (карточка выбирается,
  кубик крутит сид, «Играть» играет), а глобальный Enter остаётся для фокуса
  на фоне. Проверку в приёмке — на фокус карточки 128, а не только на мышь.

### BUG-07-03 · Журнал не обновляет повтор события: старые координаты, время и «×1» · major

- **Файл:** `game/js/hud.js:2331-2349` (`refreshEvents`), `game/js/hud.js:2351-2399`
  (`paintEventLog`), `mapgen2/js/events.js:69-98` (`throttled`).
- **Что происходит.** `Events.throttled` при повторе атаки **не создаёт новое
  событие**: у того же объекта растут `count`, обновляются `t`, `x`, `y`.
  HUD решает «перерисовывать ли» только по `id` последнего события:

  ```js
  // hud.js:2344-2348
  var last = list.length ? (list[list.length - 1].id || 0) : 0;
  if (last === evLog.lastId) return;      // count/t/x/y могли измениться
  evLog.lastId = last;
  evLog.items = list.slice(-8).reverse();
  paintEventLog(st);
  ```

  После повтора id тот же → `return` → DOM остаётся с прежним `×N`, временем и
  `data-x/data-y`. Кнопка «→» в строке ведёт к **старому** месту удара. При
  этом кнопка угрозы `#threatGo` ведёт правильно: `evLog.threat`
  пересчитывается до раннего `return` (строки 2335-2343).
- **Репро:** в партии получить первый удар (журнал открыт на широком окне),
  затем второй удар того же владельца в пределах `ATTACK_GAP = 8 с` и в другом
  месте. В мире `count=2, x=31, y=32`; в журнале по-прежнему `×1`, точка
  10,10.
- **Доказательство (проба):**

  ```
  world:       { count: 2, x: 31, y: 32, t: 0.4 }
  afterFirst:  { count: "", x: "10", y: "10" }
  afterRepeat: { count: "", countHidden: true, x: "10", y: "10",
                 last: "на деревню напали · 0:00" }
  ```

  Приёмка НЕ ловит: в `game/tools/menu.js` нет ни одной проверки журнала
  (строки с `eventLog` — ноль); `mp.js` тоже.
- **Уверенность:** высокая (поведение воспроизведено в браузере).
- **Правка:** подпись для перерисовки должна включать изменяемые поля **всех**
  показываемых событий, а не только `id`:

  ```js
  var sig = list.slice(-8).map(function (e) {
    return e.id + ':' + (e.count || 1) + ':' + Math.round((e.t || 0) * 100) +
      ':' + e.x + ',' + e.y;
  }).join('|');
  if (sig === evLog.sig) return;
  evLog.sig = sig;
  evLog.items = list.slice(-8).reverse();
  paintEventLog(st);
  ```

  (`last.ev` может быть и не верхним событием: атака → разрушение → повтор
  атаки, — поэтому подпись по всему списку, а не по `list[last]`.)

### BUG-07-08 · На телефоне бейдж сети накрывает шапку журнала событий · minor

- **Файл:** `game/css/hud.css:1748-1758` (бейджи `position: absolute; top: 52/80/108px`
  при `max-width: 560px`), `game/css/hud.css:1763-1766` (журнал во всю ширину).
- **Что происходит.** На экране ≤560 px `.hud-top-right` стоит на `top: 10px`,
  бейджи вынесены из потока на `top: 52px` (то есть 62 px от верха), а журнал —
  в левой колонке, и его шапка начинается на 64 px. Бейдж «организатор» /
  «нет связи» ложится на правую часть шапки: обрезает последнее событие и
  стрелку «▾» (на 360 px площадь пересечения 1580 px²). В сети это видно
  постоянно.
- **Репро:** 360 × 640, партия, показать `#netBadge` («организатор») и
  раскрытый журнал; бейдж перекрывает шапку.
- **Доказательство (проба):**

  ```
  narrow: { badge: [269, 62, 350, 84], head: [10, 64, 350, 108],
            overlap: 1580, vw: 360, logW: 340 }
  ```

  Приёмка НЕ ловит: узкое окно в `menu.js:1436-1481` — 760 × 720, где
  `@media (max-width: 560px)` вообще не включается; мобильный профиль
  (`pointer: coarse`) не эмулируется.
- **Уверенность:** высокая.
- **Правка:** на ≤560 не ставить бейджи абсолютом поверх левой колонки.
  Самый простой вариант — увести их в свободный нижний левый угол
  (`position: fixed; left: 10px; bottom: 10px; top: auto; right: auto;`

  `setNetPing`/`setSpectator`/`paintSimBadge`) и на телефоне сузить журнал
  на ширину бейджа. Фиксированный `top: 52px` без запаса под шапку журнала —
  причина.

### BUG-07-09 · Карточка размера не поднимается и не нажимается: `animation-fill-mode: both` съедает `transform`; приёмка «поднята» ловит единичную матрицу · cosmetic

- **Файл:** `game/css/menu.css:192` (`.size-card { animation: card-in .42s ... both; }`),
  `game/css/menu.css:203-216` (`.size-card:hover`, `:active`, `.selected` с
  `transform`), `game/tools/menu.js:379-382` (проверка приёмки).
- **Что происходит.** `card-in` анимирует `transform`, а `fill-mode: both`
  оставляет финальный кадр `translateY(0) scale(1)` навсегда. Анимации в
  каскаде выше обычных объявлений, поэтому `transform: translateY(-4px)` у
  `.selected`, `translateY(-3px)` у `:hover` и `translateY(2px)` у `:active`
  не применяются никогда. Карточка выбирается (рамка, печать), но не
  «поднимается» и не утапливается. Приёмка при этом зелёная, потому что
  проверяет `getComputedStyle(c).transform !== 'none'`, а матрица
  `matrix(1,0,0,1,0,0)` не `none`.
- **Репро:** выбрать карточку 96; `getComputedStyle(...).transform` —
  единичная матрица, `animationName: card-in`, `fillMode: both`.
- **Доказательство (проба):**

  ```
  cardCss: { transform: "matrix(1, 0, 0, 1, 0, 0)",
             animation: "card-in", fill: "both", selected: true }
  ```

  Приёмка НЕ ловит: она и не может — её условие выполняется на сломанном
  (см. `menu.js:379-382`).
- **Уверенность:** высокая (вычисленный стиль).
- **Правка:** `animation: card-in .42s var(--ease-pop) backwards;` — после
  конца анимации `transform` снова берётся из правил `.selected`/`:hover`/
  `:active`, а до старта (задержки 0.12–0.30 с) держится начальный кадр.
  Проверку в приёмке заменить на `new DOMMatrix(cs.transform).m42 < -1`
  (для `.selected`).

## Проверено и НЕ баг

- **«Меню» поверх итога.** `#pause { z-index: 7 }`, `#result { z-index: 8 }`
  (`hud.css:1337-1340`), `#result` идёт позже в DOM. Даже если ратуша пала
  при открытой доске и `Hud.onDefeat` не закрывает `#pause`, экран итога
  выше; «Продолжить» под ним не нажать, а «В главное меню» уводит через
  `toMenu` с `closePause`. Намеренная иерархия, не баг.
- **«Меню» — не пауза.** `Play.pause()` (`play.js:2719-2726`) только меняет
  `mode`, `running` не трогает; `Hud.tick` обновляет числа на доске
  (`hud.js:1077-1081`); приёмка это проверяет (5 с мира за меню). Не баг.
- **HUD не ест клики по карте.** `#hud > * { pointer-events: none }`, а
  ловят только `.plaque`, `.build-menu`, `.place-bar`, `.edit-bar`,
  `.debug-drawer.open`, `.minimap-frame`, кнопки и поля (`hud.css:30-41`).
  Панель найма проверена приёмкой на `elementFromPoint` и на «клик по кнопке
  не выбирает постройку» (`menu.js:1074-1095`). Контейнеры пропускают мышь;
  журнал — отдельная находка 05, не общее правило.
- **Кнопка у кромки.** Накладка `button:active::before` считается от
  `--press` и стоит у всех кнопок игры (play 7, wood 4, icon 3, hire 3,
  mini 2, dice 4, size 2, event-log 2, threat 3); приёмка жмёт 1 px от
  кромки с паузой 240 мс. Единственное исключение — карточки размера, у
  которых `transform` вообще не работает (находка 09), но у них и нет
  уезжающей области, так что клик не терялся.
- **Клавиши по `KeyboardEvent.code`.** В игре все буквенные горячие клавиши
  идут через `Keys.name`: `play.js:4541-4598` (WASD/R/O/H/C/V/F/N/Esc),
  `hud.js:497-533` (T/Esc), `menu.js:91-101` (R/Enter). Стрелки в меню
  сравниваются с `e.key`, но `ArrowLeft/Right` от раскладки не зависят.
  `Keys.typing` закрывает `input/select/textarea/contenteditable`; сид и
  поля лобби защищены. Не баг.
- **Рост журнала.** `Events.MAX = 40`, HUD показывает последние 8
  (`hud.js:2347`), новая партия чистит `evLog.lastId/items/threat` в
  `onStart` (`hud.js:1032-1039`); старые события после новой партии не
  всплывают. Предел есть, дублей от новой партии нет.
- **Лобби после старта.** `startNet` (`boot.js:125-135`) первым делом прячет
  `#lobby`, `Lobby.enterGame` останавливает опрос; `/api/status` при
  `j.started` зовёт `handleStart` (`net.js:618-637`), поэтому даже без SSE
  клиент получает старт, а не остаётся в лобби. Кнопка «Начать игру» видна
  только хосту и только при `canStart` (`lobby.js:487-501`). Намеренно.
- **Ссылка лобби.** `inviteLink` собирает адрес из `preferredOrigin()`
  (туннель → не-loopback origin → hamachi/lan/vpn/public), а не из
  `location.origin`; `?lobby=CODE` подставляет код и открывает лобби. Не баг.
- **Всплывашки в сети.** `toast()` при `state.netRole` молчит целиком
  (`hud.js:2539-2548`); это правило 2026-10-24, а не потеря сообщений. Не баг.
- **Клик по миникарте.** `pointerdown` переводит CSS-пиксели в координаты
  движка через `MM / rect.width`, зовёт `renderer.pickMinimap` и
  `centerOn`, снимает `follow`. Координаты и DPR сходятся; не баг. (См.
  «Не проверено» про подлёт камеры.)
- **Экран итога не поверх главного меню.** `boot.js:391-393` не показывает
  defeat при открытом `Menu`; это записанное правило, не баг. Появление итога
  поверх **лобби** — сценарий, которого правило не покрывает, но его я не
  воспроизводил (см. «Не проверено»).
