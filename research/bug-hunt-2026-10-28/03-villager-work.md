# 03-villager-work — работа и экономика жителей (4tox, 610db26)

## Сводка

Проверенная область: `mapgen2/js/villager.js` (цикл лесоруба, выбор дерева и места,
переноска/сдача, ученик/воин), `mapgen2/js/session.js` (наём, тренировка,
`rebalanceGarrison`, рождение), `mapgen2/js/buildings.js` (`WORK`/`TRAIN`,
`remove`/`ruin`), `mapgen2/js/simulation/commands.js` (hire/train/fire/edit),
`mapgen2/js/serialize.js`/`hydrate` и потребители `game/js/hud.js` / `play.js`.

Найдено 6 дефектов: 3 существенных (двое рубят в одной клетке; тренировка сверх
мест назначения оставляет воинов «в никуда»; дерево погибшего лесоруба
становится вечно занятым) и 3 малых/косметических (выбывший игрок продолжает
командовать; снос дома оставляет `v.home` на несуществующей постройке;
«+4» о сдаче считается по индексу массива). BUG-03-01 воспроизводится в
штатной стартовой деревне без правок мира (7 из 25 сидов), BUG-03-03 — после
смерти лесоруба в бою (метка дерева остаётся на мёртвом).

Запускались только node-приёмки/скрипты: `node mapgen2/tools/lumbercamp-move.js`
— ПРИНЯТО; `node mapgen2/tools/garrison.js` — ДРУЖИНА ПРИНЯТА; браузерные
`menu.js`, `mp.js`, `mapgen2/tools/game.js` не запускались (их гоняет
координатор). Репозиторий не менялся, кроме этого отчёта.

## Находки:

### BUG-03-01 · Двое рабочих рубят, стоя в одной клетке · major

- Файл: `mapgen2/js/villager.js:1027` (`standCells`), `mapgen2/js/villager.js:1483`
  (`plan`), `mapgen2/js/villager.js:1327` (`routeToTree`); приёмка
  `mapgen2/tools/lumberjack.js:542-551` и `:767-770`.

  этой клетке уже стоит/рубит другой житель и что другой рабочий уже назначил
  её себе в `v.goal`. Два соседних дерева (в т.ч. по диагонали) имеют общий
  сосед — два лесоруба приходят в одну клетку и рубят разные деревья 3+ секунды.
  Ожидалось: двое в одной клетке не стоят (комментарий
  `planWorkSpot`, `mapgen2/js/villager.js:1795-1797`: «Двое в одной КЛЕТКЕ — это
  и есть то, чего быть не должно»; приёмка `lumberjack.js` п.6: «не СТОЯТ в
  одной клетке — ни в лагере, ни под деревом»). Фактически: тела в 0.38 клетки
  друг от друга, спрайты накладываются.
- Репро (штатная деревня, без правок мира): карта 64, сид `chop-6`, старт
  одиночной партии, нанять всех трёх в стартовый лагерь, крутить

### BUG-03-02 · Тренировка сверх мест назначения: воины выходят «в никуда» · major

- Файл: `mapgen2/js/session.js:1409-1435` (`warriorsAt`/`garrisonAt` не считают
  учеников), `:1527-1553` (`canTrain` спрашивает `destinationFor`, не вычитая
  уже обучаемых), `:1588-1590` (ученику ставится подсказка `warcamp`/`station`),
  `mapgen2/js/session.js:2999-3054` (`finishTraining`), `game/js/hud.js:1941-1947`
  (пакет «Тренировать свободных» считает только `trainingSlots`).
- Что происходит: `destinationFor`/`warcampRoom`/`barracksRoom` считают только
  `v.warrior && !v.trainee`, поэтому места, обещанные уже обучаемым, остаются
  «свободными». Пакетная кнопка HUD берёт `trainingSlots - trainees` (3), а не
  `trainingBatchInfo.count` (в котором учтён `destRoom`), и отправляет трёх
  учеников туда, где есть одно место. После пяти секунд первый занимает место,
  остальные получают `destinationFor() === null`, `v.warcamp = v.station = null`,
  `state='stand'` — воин есть, идти ему некуда; сам он не переучивается и не
  умирает, стоит до конца партии (пока не освободится чужое место).
  Правило заказчика (AGENTS, «Тренировка запрещена, когда заняты и лагеря, и
  дворы») нарушено: тренировка разрешена, хотя мест на всех не хватает.
- Репро: 96-я карта, `Session.startMultiCore`/`startHomeCore`, деревня, казарма
  и военный лагерь; 20 жителей помечены воинами в лагере, 9 — во дворе казармы,
  трое свободны. `Session.armyRoom(...) === 1`,
  `Session.trainingBatchInfo(bar,...).train.count === 1`. Нажатие
  «Тренировать свободных» (или три одиночных «Тренировать» подряд) даёт три
  `Session.train(...).ok === true`. Через 37.6 с: воинов 32, в лагере 20, во
  дворе 10, двое — `state='stand'`, `!warcamp && !station`:
  ```
  armyRoom 1 batch count 1
  canTrain 30 true / 31 true / 32 true
  HUD batch would send 3
  after 37.6 s: warriors 32 camp 20 yard 10 nowhere 2 31:stand,32:stand
  ```
- Доказательство:
  ```js
  // session.js:1413 и :1428 — ученик с обещанным местом не считается
  if (v && v.warrior && !v.trainee && !v.station && v.warcamp === camp) n++;
  if (v && v.warrior && !v.trainee && v.station === barracks) n++;
  ```
  ```js

  var freeTrain3 = B3.trainingSlots(camp) - S3.traineesOf(camp, list).length;
  ...
  var rr = global.Play.localCommand({ type: 'train', ... });
  ```

  Приёмки НЕ ловят: `garrison.js` тренирует по одному и ждёт окончания; в

- Уверенность: высокая (воспроизведено дважды, в т.ч. с точной копией цикла

- Правка: в `canTrain` вычитать места, уже обещанные ученикам:
  `var pending = villagers.filter(x => x.trainee && (x.warcamp===dest.camp ||
  x.station===dest.barracks)).length; var room = dest.camp ?

### BUG-03-03 · Дерево, помеченное погибшим лесорубом, не может срубить никто · major

- Файл: `mapgen2/js/combat.js:638-658` (`killVillager`), `mapgen2/js/villager.js:948-951`
  (`treesNear` отбрасывает чужую метку), `mapgen2/js/villager.js:1572-1579`
  (`unmark`). Связанное: `game/js/play.js:654-670` (`normalizeResumedVillagers`
  тоже обнуляет `v.tree` без `unmark` при восстановлении из контрольной точки).
- Что происходит: смерть обнуляет `employer`/`trainee`/`warcamp`, но не
  `v.tree` и не `tree.mark`. Погибший удаляется из списка жителей, а дерево
  остаётся в `world.objects` с `mark` на мёртвого. `treesNear` не отдаёт дерево
  никому, кроме владельца метки (`tree.mark !== awayFrom`), а снять метку уже
  некому: `unmark` зовут только `plan`/`fell`/`fire`/`stepOut`/`rescueMove`, а
  мёртвого в этих путях нет. Дерево навсегда выпадает из лесосеки; при смерти
  рубщика оно к тому же остаётся недорубленным. Лес в игре не растёт — потеря
  необратима. При серии смертей рабочих «нет леса» наступает раньше, хотя
  деревья стоят.
- Репро: одиночная/сетевая карта 64, нанять трёх, дождаться, пока у одного
  появится `v.tree` (например, на 211-м тике у №3), вызвать
  `Combat.killVillager(v, world)` и прокрутить тик. Вывод `/tmp/t1.js`:

  ```
  after kill mark? true in objects? true
  victim removed? true mark still? true
  fresh worker chose marked tree? false
  ```

- Уверенность: высокая.
- Правка: в `killVillager` до обнуления полей:

### BUG-03-04 · Выбывший игрок продолжает нанимать, тренировать и сносить · minor

- Файл: `mapgen2/js/simulation/commands.js:242-255` (hire/train/fire) и
  `:216-241` (edit) — нет проверки `town.alive`; для контраста `:152-157`
  (build) её имеет.
- Что происходит: после падения ратуши город помечается `alive=false`, и
  `Play.canCommand` закрывает игроку стройку и приказы. Сервер же для
  hire/train/fire/edit проверяет только владельца постройки/жителя, но не
  живость города: выбывший (или успевшая прийти после падения команда) успешно
  нанимает, тренирует воинов, поворачивает/удаляет собственные постройки.
  `build` при этом честно отвечает «ваша деревня больше не в игре» — то есть
  проверка задумана, но в трёх ветках забыта.
- Репро (node, `makeSim` multi 2): `Session.townById(world,0).alive = false`;
  `Commands.apply({type:'hire', owner:0, payload:{campId, villagerId}})` →
  `status='applied'`, у жителя появляется `employer`; `train` → применён,
  `trainee=true`; `edit delete` дома → применён, дом удалён. Для сравнения
  `build` → `rejected / town_gone`:
  ```
  hire after defeat: applied employer? true
  train after defeat applied trainee? true
  edit(rotate townhall) after defeat applied rot 180
  edit(delete house) after defeat applied house left? false
  build after defeat: rejected ваша деревня больше не в игре
  ```
- Доказательство:
  ```js
  // commands.js:242-252 — ветка не спрашивает town
  if (cmd.type === 'train' || cmd.type === 'hire' || cmd.type === 'fire') {
    ...
    var answer = cmd.type === 'train' ? S.train(...) : ...;
  ```
  Приёмка НЕ ловит: `mp.js` проверяет команды живых игроков; сценария
  «выбывший шлёт hire/train/edit» в его списке нет (стройка выбывшего
  проверяется, потому что у неё проверка есть).
- Уверенность: высокая (поведение), последствия ограничены: победитель уже
  определён, дружина выбывшего в бою не участвует, но мир после выбывания
  продолжает мутировать вопреки правилу «выбывший наблюдает».
- Правка: в начале веток hire/train/fire и edit:
  `var town = townOf(sim, cmd.owner); if (!town || town.alive === false) return
  reason('town_gone', 'ваша деревня больше не в игре');` (2-3 строки; для edit

### BUG-03-06 · «+4» о сдаче привязывается к номеру в массиве, а не к жителю · cosmetic

- Файл: `game/js/play.js:212` (`deliveredSeen = []`), `:2587-2595`
  (`stepDeliveries`), удаление мёртвых `:2487`.
- Что происходит: `deliveredSeen[i]` — массив по индексу в `state.villagers`.
  После смерти/удаления жителя индексы сдвигаются: у следующего жителя
  «прошлая» сдача оказывается уже учтённой, поэтому его первая сдача не даёт
  события «+4»; последующие сравнения тоже сдвинуты и могут дать событие не
  тому жителю. `state.logs` при этом правильный (он из `town.logs`), ломается
  только обратная связь HUD/всплывашка.
- Репро: запустить двух лесорубов, убить первого (или уволить) в момент, когда
  второй несёт брёвна; следующая сдача второго не даёт `type:'delivery'` с его
  `villager`, либо событие показывает не того.
- Доказательство:
  ```js
  for (var i = 0; i < list.length; i++) {
    var was = typeof deliveredSeen[i] === 'number' ? deliveredSeen[i] : 0;
    var now = typeof list[i].delivered === 'number' ? list[i].delivered : 0;
    if (now > was) grew.push(list[i]);
    deliveredSeen[i] = now;
  }
  ```
  Приёмка НЕ ловит: `menu.js` проверяет «+4» на живых лесорубах без смерти
  между сдачами; `lumberjack.js` тоже не убивает носильщика.
- Уверенность: высокая (код), влияние — только показ события.
- Правка: ключ по `v.id` (`deliveredSeen[v.id]`) и чистить при удалении жителя;
  2-3 строки (или хранить `delivered` прямо на жителе и сравнивать с прошлым
  кадром).

## Проверено и НЕ баг (со ссылкой на правило)

- **Казна при смерти носильщика, сносе/разрушении лагеря, увольнении с грузом.**
  `fell` переводит ходку в `inTransit` (`villager.js:2555-2557`), `loseCargo`
  — из `inTransit` в `lost` (`session.js:1304-1324`), `noteDeadCargo` зовётся
  до шага (`session.js:2012-2014`). Проверено в node: после kill/ruin
  `logs+4*(inTransit+lost)=4*felled`, diff=0. Правило AGENTS «Работа и брёвна».
- **Двойная сдача не начисляется.** `deposit` проверяет `v.carrying`
  (`villager.js:2601`), снимает груз ровно один раз. Правило «сдача ровно один
  раз».
- **Наём четвёртого в лагерь отклоняется, смерть/увольнение освобождает
  место.** `canHire` считает `workersOf >= workSlots` (`session.js:1198-1201`);
  проверено output `4th hire {ok:false, reason:'в лагере нет свободных мест'}`.
  Приёмка `lumberjack.js` п.1.
